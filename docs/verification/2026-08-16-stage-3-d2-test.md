# 단계 3 `S3-D2-TEST` 검증 기록 - 2026-08-16

## 1. 결과

`S3-D2-CODE`의 시작 계약과 출력 수집을 검증하는 test만 작성했다. argv 기반 콘솔 도우미 target을 추가하고 Catch2 test 29개를 넣었다. production code는 변경하지 않았다.

VS2022 Debug/Release와 VS2026 Debug의 전체 CTest가 각각 107/107 통과했다. 기존 78개에 새 test 29개가 더해진 수다. VS2022 `/analyze`는 경고 없이 통과했고 aggregate `gitman_format_check`도 통과했다. Release install 결과는 여전히 `bin/gitman.exe` 한 파일이며 도우미는 포함되지 않는다.

이번 구간에서 발견한 production 결함은 없다. 29개 test 모두 첫 실행에서 통과했다. 따라서 `S3-D2-FIX`는 사용자 확인 후 생략 대상이다.

## 2. 테스트 도우미

`tests/helpers/process_test_child.cpp`를 `gitman_process_test_child` 콘솔 실행 파일 target으로 추가했다.

- 표준 `wmain` argv를 사용한다. `S3-D2-CODE` 6장에서 확인한 대로 `cmd.exe`는 `CommandLineToArgvW` 규칙이 아닌 자체 따옴표 처리를 하므로 test 자식으로 쓸 수 없다.
- 출력은 CRT 변환을 피하려고 `WriteFile`로 raw byte를 쓴다. 잘못된 UTF-8과 진행 표시를 정확히 재현하기 위한 조건이다.
- `install` rule이 없으므로 단일 exe 배포에 영향을 주지 않는다.
- test 실행 파일과 같은 출력 디렉터리에 만들어지고, test는 `GetModuleFileNameW`로 runtime에 경로를 찾는다. 경로를 compile definition으로 넘기면 Windows 경로의 backslash가 문자열 이스케이프로 해석되는 문제가 있어 피했다.

| 도우미 명령 | 동작 |
| --- | --- |
| `exit <code>` | 지정 종료 코드로 끝난다. |
| `echo-args` | argv를 대괄호로 감싸 한 줄씩 출력한다. |
| `echo-cwd` | 현재 작업 디렉터리를 UTF-8로 출력한다. |
| `echo-env <name>` | 환경 변수 값을 출력하고 없으면 `<unset>`을 출력한다. |
| `emit <bytes> [stream]` | 지정 스트림에 지정 크기 이상의 결정적 줄을 출력한다. |
| `interleave <count>` | stdout과 stderr에 번갈아 출력한다. |
| `emit-bytes <hex>` | 지정 byte를 그대로 출력한다. code page fallback test용으로 미리 넣었다. |
| `emit-mixed` | 한글 CRLF 줄, 잘못된 byte, 진행 표시 두 개와 줄 끝 없는 tail을 낸다. |
| `emit-split` | 3 byte 문자를 두 번의 쓰기로 나눠 보낸다. |
| `read-stdin` | stdin을 읽어 즉시 EOF인지 확인한다. |

`sleep`과 `spawn-child`는 timeout 및 취소 검증용이므로 `S3-D4-TEST`에서 추가한다.

| 캡처 상한 | 상한까지만 수집하고 pending을 내보낸 뒤 절단 표시를 세우며 이후 append는 무시한다. |

| 진행 tail flush | flush 시점에 `\r`이 대기 중이면 progress 레코드로 내보낸다. |

## 6. 발견한 결함

없다. 29개 test 모두 첫 실행에서 기대한 동작대로 통과했다.

`S3-D2-CODE`에서 임시 프로그램으로 확인했던 항목은 이번 구간에서 저장소 test로 대체됐다. 대용량 출력은 임시 확인의 8 MB에서 4 MB로 낮췄다. CTest 실행 시간을 늘리지 않으면서 교착 없음과 pipe backpressure 처리를 확인하는 데 충분하고, 상한 초과 절단은 별도 test가 담당한다.
