# 검증 기록 - 단계 7 `S7-D3` update 실행 UI

## 1. 개요

- 날짜: 2026-08-19
- 대상: `S7-D3` (docs/stage-7-plan.md 5장)
- 진행 방식: 사용자 위임에 따른 자동 진행

## 2. 구현 내용

- `card_view_model`에 `can_change`(변경 작업 시작 가능)와 `change_running`(변경
  작업 실행 중)을 추가했다. `can_change`는 로컬 조회가 끝난 준비 상태의 활성
  카드만 참이며, 실제 보호 정책은 provider preflight가 실행 직전에 다시 검사한다.
- **카드 update 버튼을 활성화했다** (REQ-006).
  - 준비된 Git 카드: 확인 overlay를 연다 (`show_update_options_intent`).
  - 준비된 SVN 카드: option이 없으므로 곧바로 실행한다 (`request_update_intent`).
  - 변경 작업 실행 중: 중지 버튼(`stop-circle`)으로 바뀌어
    `cancel_operation_intent`를 보낸다.
  - 준비되지 않은 카드: 비활성 + 사유 tooltip.
- **update 확인 overlay** (`presentation/ui/update_overlay_element`): 화면을 dim
  배경으로 덮고 panel에 제목, `git pull --ff-only` 안내, `submodule 함께 갱신`
  checkbox(기본 off, ADR-003), 실행·취소 텍스트 버튼을 담는다. 배경 클릭과 Esc가
  취소이고 panel은 클릭을 흡수한다. overlay 상태(대상 카드, option)는 logic이
  소유하고 view snapshot의 `update_overlay`로 게시된다.
- logic: overlay 열기(busy 카드 거부)·option 변경·확인(update 시작과 overlay
  닫기)·취소를 처리한다. 문서 교체 시 overlay를 닫는다.
- interaction: Esc는 drag 취소 → overlay 닫기 → 선택 해제 순서다.
- dialog용 텍스트 버튼과 checkbox 줄은 overlay 구현 파일의 지역 element로 두어
  공용 계층을 늘리지 않았다.

## 3. 테스트

새 test 5개 (전체 CTest 572 → **577**).

- overlay 열기(기본 option off), option 변경, 확인 시 update 제출(option 전달)과
  overlay 닫힘.
- 취소는 작업을 만들지 않고, busy 카드에는 overlay가 열리지 않는다.
- 카드 update 버튼의 종류·상태별 배선 4경우(Git overlay, SVN 즉시 실행, 실행 중
  중지 버튼, 준비 전 비활성).
- overlay tree의 checkbox·실행·취소·배경 클릭 배선과 Esc 취소.
- **실제 Git 저장소의 executor update end-to-end**: bare remote에 새 커밋을 민
  뒤 behind인 clone을 update → fast-forward 성공, 실행 직후 재조회 snapshot,
  프로세스 출력의 로그 event 스트리밍을 실측했다 (Git 없는 호스트는 skip).
