## 5. 수동 검증 checklist (사용자)

자동 test가 다루지 못하는 창 기반 확인 항목이다.

1. 실제 저장소 문서를 열고 카드를 선택하면 하단 로그 pane이 나타난다.
2. 준비된 Git 카드의 update 버튼이 확인 overlay를 열고, 실행하면 로그 pane에
   시작·출력·완료가 실시간으로 쌓인다.
3. update 실행 중 update 버튼이 중지 버튼으로 바뀌고, 누르면 취소가 로그에
   남으며 카드 상태가 복구된다.
4. switch 버튼이 dialog를 열고 원격 브랜치가 로컬보다 위에 표시된다. 후보 선택
   후 전환하면 카드의 브랜치 표시가 바뀐다.
5. tracking branch가 없는 원격 브랜치는 `브랜치 만들고 전환` → `생성 확인` 두
   단계를 거친다.
6. dirty 작업 트리에서 update·switch가 차단 사유를 로그와 dialog에 표시한다.
7. 로그 pane의 필터·복사(클립보드 확인)·지우기·자동 스크롤 토글이 동작한다.
8. 두 카드의 update를 연달아 실행해도 각 카드 로그가 섞이지 않는다.
9. dialog·overlay가 열린 동안 Esc·배경 클릭으로 닫히고 창 이동이 계속 동작한다.

## 6. 알려진 한계와 이월 항목

- SVN 실행 경로(후보 표시·update·switch)는 fake runner 검증까지다. 실제
  `svn.exe` 실측은 단계 8이다 (2026-08-17 사용자 방침 유지).
- 실제 네트워크 원격과 인증 필요 동작은 단계 8이다. 인증 필요 시 비대화형
  옵션으로 즉시 실패하는 계약은 단계 3~4 test가 보장한다.
- 로그 pane의 시각적 스크롤 막대와 progress record 접기는 후속 항목이다.
- 환경설정 화면(Git/SVN 경로 편집 UI)과 탐색 후보 선택 등록 dialog는 별도 검수
  항목으로 남긴다 (stage-7-plan 3장).
- switch dialog의 후보 행은 전량 생성 후 화면 밖을 숨긴다. 후보 수백 개
  저장소에서 필요하면 가시 범위 생성으로 바꾼다.
