# 실환경 피드백 반영 설계

상태: **승인** (2026-08-20 작성, 2026-08-20 검수 승인)

2026-08-20 실환경 사용 피드백 5건의 설계를 기록한다.

1. 대형 저장소에서 상태 확인이 타임아웃으로 실패한다 (실측 5~10분 소요)
2. "미추적"의 의미가 불명확하고, 미추적만으로 업데이트가 실패하는 경험이 나쁘다.
   상단 목록 + 하단 diff viewer 구성의 확인 다이얼로그가 필요하다
3. 카드 컨텍스트 메뉴가 필요하다 (`저장소 열기`, `미추적 확인` 등)
4. 정렬 기능이 쓸모없다. 문서 순서 고정 + 드래그 재정렬만 남긴다
5. SVN 전환 다이얼로그가 사실상 동작하지 않는다. TortoiseSVN repo-browser류의
   UI/UX가 필요하다

## 1. 상태 확인 타임아웃

### 1.1 현황과 원인

타임아웃은 `vcs_limits_for`(`vcs_execution_policy.cpp`)의 명령 부류 단위 고정값이다.
`git status`/`svn status`는 `local_query` = **30초**라 대형 저장소에서 반드시
실패한다. `refresh`의 `fetch --prune`도 `remote_query` = **120초**로 부족할 수 있다.

### 1.2 결정

명령 부류의 기본 상한을 실측에 맞게 고치고, 상태 확인은 문서 설정으로 조정할
수 있게 한다 (2026-08-20 검수: 설정 항목까지 추가 → 2026-08-20 재검수 반영).

| 부류 | 현재 | 변경 | 근거 |
|---|---|---|---|
| `local_query` | 30초 | **600초** (설정 가능) | status 실측 5~10분 |
| `remote_query` | 120초 | **600초** (설정 가능) | 대형 저장소 fetch도 같은 규모 |
| `update` | 600초 | **무제한** | 실측 최대 3시간. 가늠해 자르지 않고 종료는 명시적 취소가 담당 (재검수 지시) |
| `tool_probe` / `switch_target` | 5/300초 | 유지 | 문제 보고 없음 |

`local_query`에는 `rev-parse` 같은 빠른 명령도 섞여 있어, 진짜로 걸린 프로세스의
실패 감지가 늦어진다. 이는 감수한다 — worker lane은 project 단위라 다른 저장소
작업을 막지 않고, 취소(token)는 타임아웃과 무관하게 즉시 동작한다.

### 1.3 설정 항목

`workspace_settings`(문서 `settings` object)에 optional 필드 1개를 추가한다.
로컬·원격 조회에 함께 적용되며, `git_executable`과 같은 규칙으로 schema
version은 올리지 않는다. (재검수 반영: 항목을 "상태 확인" 하나로 통합, update는
무제한이라 설정 대상이 아니다.)

```json
"settings": {
    "query_timeout_seconds": 600
}
```

- 없으면 1.2의 새 기본값. 허용 범위 **10~3600초**, 벗어나거나 타입이 다르면
  경고 진단만 남기고 기본값을 쓴다(문서 열기는 실패하지 않는다).
- 반영 경로: `vcs_limits_for`/`make_vcs_process_request`가 override를 받도록
  확장하고, provider에 설정값이 전달되는 기존 경로(실행 파일 경로와 동일)를 쓴다.
- 환경설정 다이얼로그에 "상태 확인 제한 시간 (초)" 행을 추가한다. 값 칸은
  **숫자만 받는 텍스트 박스**다 (재검수 지시). 이를 위해 문자 입력 경로를
  신설한다: `WM_CHAR` → `character_typed_event` → (환경설정 dialog가 열려 있을
  때만) `edit_settings_timeout_intent` → logic이 숫자(0~9)와 backspace만 초안에
  반영. 빈 초안 = 기본값(안내 문구 표시), 범위 밖 값은 검증 메시지와 함께 저장
  버튼 비활성(실행 파일 경로 검증과 같은 패턴).
- **초점과 caret** (추가 지시): `interaction_snapshot::focused_input`을 신설한다.
  초점은 **텍스트 박스를 눌러야** 생긴다(재검수 지시: 열릴 때 자동 초점 없음).
  다른 곳을 누르거나 dialog가 닫히면 풀린다. 초점을 받은 동안 글 끝에서 caret이
  **깜빡이고**(반주기 530ms, 초점 시각이 위상 기준이라 받는 순간 켜짐) 테두리를
  강조한다. 다시 그리기는 UI thread의 caret timer가 다음 뒤집힘 시점에
  일으킨다(tooltip timer와 같은 패턴). 문자 입력은 초점을 가진 칸으로만 간다.
  커서 이동·선택은 만들지 않는다(끝에서만 지우고 붙임).
- **즉시 갱신** (추가 지시): 키 입력이 한 박자 늦게 보이던 원인은
  `publish_snapshots`가 view(wake 신호)를 먼저 게시하고 tree를 나중에 게시하는
  race였다 — wake를 받은 UI thread가 이전 tree로 그린 뒤 새 tree에는 신호가
  없어 다음 이벤트까지 기다렸다. 게시 순서를 tree → view로 바꿔 wake 시점에
  항상 최신 tree가 있게 한다.
- 테스트: 기본값 상수 단정 갱신, override 반영/범위 검증/직렬화 왕복, 문자
  입력 편집·범위 차단·저장 반영.

## 2. 미추적(untracked) 경험 개선

### 2.1 용어와 현황

"미추적"은 **버전 관리에 아직 추가(add)되지 않은 새 파일**이다. 현재 파서는
미추적만 있어도 `working_tree_state::modified`로 판정하고, update preflight가
`state != clean`이면 `working_tree_dirty`로 차단한다. 사용자에게는 "커밋하지 않은
변경이 있어 갱신하지 않았습니다"라는 부정확한 문구가 보인다.

### 2.2 정책 변경: 미추적만으로는 차단하지 않는다

도메인에 판정을 분리한다.

```cpp
// working_tree_summary (repository_snapshot.h)
bool has_tracked_changes() const;   // modified/conflict/진행 중 작업 — 차단 대상
bool has_untracked_only() const;    // 미추적만 존재 — 차단하지 않음
```

- **update**: `evaluate_git_update_preflight` / `evaluate_svn_update_preflight`가
  `has_tracked_changes()`일 때만 `working_tree_dirty`를 반환한다. 미추적만 있으면
  진행한다. Git pull은 미추적 파일을 덮어쓰게 되는 경우 스스로 중단하고 작업
  트리를 건드리지 않으며, SVN update는 미버전 파일과 충돌 시 tree conflict로
  남긴다 — 도구 자체의 보호가 있으므로 앱이 선제 차단할 이유가 없다.
- **switch는 완화하지 않는다** (2026-08-20 검수: 업데이트만 허용). 전환은 작업
  복사본 내용이 통째로 바뀌므로 미추적이 있어도 현행대로 차단을 유지한다
  (`is_safe_for_change` 그대로).
- 실행 결과 도구가 중단한 경우는 기존 실패 분류/로그 경로로 그대로 보고된다.
- 문구: `working_tree_dirty` 메시지를 "커밋하지 않은 **수정**이 있어 갱신하지
  않았습니다."로 조정한다(충돌은 별도 사유·문구가 이미 있음). 로컬 변경 확인
  안내 문장은 2.3 다이얼로그가 생기는 F4에서 덧붙인다.

### 2.3 로컬 변경 확인 다이얼로그

카드의 미추적/변경 상태를 눈으로 확인하는 in-app 다이얼로그를 추가한다. 기존
다이얼로그 패턴(`view_snapshot`의 optional view + `build_ui_tree` 마지막 자식 +
`logic_controller` 멤버 상태)을 그대로 따른다.

**구성** — 세로 분할:

- 상단: 변경 항목 목록. 파일별로 종류 배지(`수정`/`미추적`/`충돌`/`삭제` 등)와
  경로를 표시한다. 스크롤(`scrollbar_element` 재사용), 행 클릭으로 선택.
- 하단: 선택 항목의 diff viewer. 읽기 전용 텍스트, `+`/`-` 행 색상(추가=green
  accent, 삭제=red accent), 고정폭 글꼴, 스크롤.

**데이터 흐름** — 새 query 작업 2개:

1. `query_local_changes`: 상태 확인과 같은 status 명령을 실행하되 **항목 경로
   목록을 보존**해 반환한다 (현재는 개수만 집계). 파서는 이미 항목을 만들고
   버리는 구조라 반환 모델(`local_change_entry { path, kind }` 목록)만 추가한다.
2. `query_file_diff { path, kind }`: 선택 시 lazy 실행.
   - Git 추적 파일: `git diff HEAD --no-color -- <path>` (staged+unstaged 통합)
   - SVN 추적 파일: `svn diff <path>`
   - 미추적 파일: VCS 명령 없이 파일을 직접 읽어 전체 내용을 "추가" 취급으로
     표시한다 (worker에서 읽기, UI 스레드 차단 없음)

**상한과 예외**:

- diff/내용은 256 KiB까지만 표시하고 초과 시 "…이후 생략 (N KiB)" 꼬리표를 단다.
- NUL 바이트 감지 시 "이진 파일 — 내용을 표시하지 않습니다"로 대체한다.
- 미추적 디렉터리 항목(status가 접어서 보고)은 배지에 `디렉터리`를 붙이고 diff
  대신 "미추적 디렉터리 — 내부 파일은 표시하지 않습니다"를 보여준다.
- 두 query 모두 `local_query` 부류(1장에 따라 600초)를 쓴다.

진입점은 3장의 컨텍스트 메뉴("로컬 변경 확인")와 **카드 더블 클릭**이다.
(구현 조정 2026-08-20: 상태 chip은 element가 아니라 그리기 시점에 폭이 정해져
hit 대상이 될 수 없다. chip 클릭 대신 카드 body 더블 클릭을 진입점으로 한다.)

구현 세부 (2026-08-20):

- 목록이 도착하면 첫 항목을 자동 선택해 diff까지 이어서 보여 준다.
- 목록·diff의 스크롤은 휠 전용이다(switch/탐색 dialog와 같은 방식). diff pane
  위의 휠은 diff를, 그 밖은 목록을 스크롤한다.
- 미추적 내용 읽기는 `vcs_file_probe::read_prefix` 계약을 신설해 수행한다
  (파일/디렉터리/부재 구분 + 상한 잘림). 후속 항목 5·6의 파일 내용 읽기 계약
  요구를 겸한다.
- 늦게 도착한 목록·diff 결과는 operation id로 걸러 버린다.

재검수 반영 (2026-08-20):

- **목록 행**: 미추적 항목은 `$(file)`(파일)/`$(folder)`(디렉터리) codicon을
  경로 앞에 붙이고, 전체를 흐리게(비활성 느낌) 그린다. 배지도 중립색이다.
- **외부 열기**: 행 오른쪽 끝에 `$(vscode)`(VSCode에서 열기)와
  `$(folder-opened)`(탐색기에서 열기) 아이콘 버튼을 둔다. 경로가 겹치면
  `…`으로 줄이고 아이콘은 유지한다. `ui_command`는 인자를 담지 못하므로
  `open_external_request { target, absolute_path }`를 input_action에 추가하고,
  input thread → app_runtime 큐 → UI thread(shell 실행: `explorer.exe /select`,
  PATH의 `code.cmd`) 경로를 신설했다. 절대 경로는 logic이 카드 경로와 항목
  경로를 이어 행에 싣는다.
- **2-way diff**: unified diff를 `build_two_way_diff` 순수 함수로 좌(이전)·
  우(이후) 행으로 정렬한다 — hunk 안 `-`/`+` 묶음을 순서대로 짝짓고 남는 쪽은
  빈 칸, 문맥 줄은 양쪽 동일, 구조 줄은 전체 폭. 변경 행은 좌우 반 칸에 옅은
  배경을 깐다.
- **스크롤 막대**: 목록·diff 각각에 `scrollbar_element`(끌기 가능)를 붙이고
  내용이 넘칠 때만 보인다. 막대가 보이면 행 폭을 그만큼 좁힌다.

## 3. 카드 컨텍스트 메뉴

카드 body 우클릭(`ui_trigger::right_click` — 프레임워크에 이미 존재, 등록만 하면
됨)으로 팝업 메뉴를 연다. in-app 자체 렌더로 다이얼로그 패턴을 따르되, 앵커
좌표(클릭 위치)에 붙는 소형 패널이다. 바깥 클릭·Esc로 닫는다.

**항목 (1차)**

| 항목 | 동작 |
|---|---|
| 저장소 열기 | 탐색기로 작업 복사본 폴더 열기 (`ShellExecuteW`, UI 스레드) |
| 로컬 변경 확인 | 2.3 다이얼로그 열기 |
| 상태 갱신 | 기존 refresh intent |
| 업데이트 | 기존 update intent |
| 전환… | 기존 switch 다이얼로그 |

- 진행 중 작업으로 버튼이 비활성일 때는 해당 메뉴 항목도 비활성(회색) 처리한다.
- 우클릭한 카드를 선택 카드로 만든 뒤 메뉴를 연다 (로그 pane 등 기존 선택 연동
  유지).
- `view_snapshot`에 `std::optional<context_menu_view> { owner, anchor, items }`.
- 키보드: 메뉴 열림 중 ↑/↓/Enter/Esc를 메뉴가 흡수한다.

구현 조정 (2026-08-20, F5):

- 저장소 열기는 F4의 외부 열기 경로를 재사용한다 —
  `external_open_target::explorer_folder`(`/select` 없이 폴더 자체)를 신설.
- 키보드 강조는 입력 정규화 상태(`interaction_snapshot::menu_highlight`)로
  두고, Enter는 강조 항목의 클릭 액션을 그대로 실행한다(외부 열기 포함).
  ↑/↓는 비활성 항목을 건너뛴다.
- 메뉴가 떠 있는 동안 휠은 무시한다(앵커 아래로 목록이 흘러가는 것 방지).
- 실행 중 카드의 `업데이트` 항목은 비활성이다(버튼과 달리 메뉴에 취소 항목은
  두지 않는다).

## 4. 정렬 제거 — 문서 순서 고정

이름순/상태순 정렬과 toolbar 정렬 순환 버튼(커밋 `0fe4e69`)을 **제거**한다. 카드는
항상 문서(`projects` 배열) 순서로 표시한다.

- 드래그 재정렬 → 문서 갱신 → 저장은 이미 구현·영속화되어 있으므로 그대로가
  최종 동작이 된다.
- 제거 대상: `card_sort_key` enum, `logic_controller::sort_`/`set_sort_intent`,
  `toolbar_element`의 정렬 버튼과 `next_sort_key`/`sort_tooltip`, 관련 테스트.
  `build_ordered_cards`는 문서 순서 그대로 반환하는 형태로 단순화한다.
- README "알려진 제한"의 정렬 관련 stale 문구도 함께 정리한다.
- 후속 항목 1(정렬 전환 UI)은 "구현 후 실사용 피드백으로 제거"로 기록을 남긴다.

### 4.1 드래그 UX — 카드가 통째로 떠서 따라오고 삽입 자리의 여백이 벌어진다

(2026-08-20 추가 지시) 기존의 작은 label ghost + 대상 카드 테두리 강조를
다음으로 바꾼다.

- **떠 있는 카드**: drag가 시작되면 카드 전체가 잡은 지점 그대로 포인터를
  따라온다 (`drag_payload`에 잡은 지점 offset 추가). 원래 slot에서는 그리지
  않아 목록에서 빠진 것으로 보인다.
- **삽입 여백**: 포인터 위치가 가리키는 삽입 위치의 여백이 카드 한 장 크기로
  벌어진다. 나머지 카드는 "dragged를 뺀 목록 + 삽입 여백" 기준의 slot으로
  세로 offset만 이동해 그린다. 포인터가 목록 밖이면 여백은 원래 자리다.
- **tree는 불변 유지 (ADR-004)**: 배치(bounds)·hit test는 그대로 두고 **그리기
  offset만** 이동한다. drag 상태는 `interaction_snapshot`으로 이미 draw에
  전달된다. 여백 위치 계산과 drop 대상 계산이 같은 순수 함수
  (`card_drag_insertion_slot`/`card_drag_offset`, `list_metrics`)를 쓰므로
  벌어진 자리와 실제 놓이는 자리가 항상 일치한다.
- **drop 대상을 목록 수준으로**: 카드별 drop 대상(위/아래 절반)을 제거하고
  `card_list`가 유일한 drop 대상이 된다. 삽입 경계는 각 카드의 세로 중앙이라
  체감 규칙(위 절반=앞, 아래 절반=뒤)은 기존과 같고, 카드 사이 여백에
  놓아도 동작한다. 제자리 drop은 intent를 만들지 않는다. 목록이 hit 대상이
  되므로 빈 영역 클릭의 선택 해제는 목록에도 등록한다.
- 화면 밖으로 스크롤되어 카드 element가 없는 경우(드래그 중 휠 스크롤)만
  기존 소형 label ghost로 대체한다. 여백 이동의 easing 애니메이션은 하지
  않는다(입력마다 즉시 다시 그리는 렌더 모델 유지). 드래그 중 목록 가장자리
  자동 스크롤은 후속 항목으로 남긴다.

## 5. SVN repo-browser 전환 다이얼로그

### 5.1 현황과 원인

SVN 전환 후보는 문서의 `svn_switch_targets` 허용 목록**만** 쓰는데, 이 필드를
채우는 자동 경로가 없어 일반 문서에서는 **항상 빈 목록**이다. 이것이 "사실상
동작하지 않는" 원인이다.

### 5.2 결정: 저장소 실조회 기반 트리 브라우저

SVN 전환 다이얼로그를 TortoiseSVN repo-browser처럼 저장소 트리를 직접 탐색하는
UI로 바꾼다. Git 전환 다이얼로그는 현행 유지.

**조회 흐름**

1. 열기 시 `svn info --show-item repos-root-url`(로컬, 기존 빌더)로 루트 URL과
   현재 전환 위치를 얻는다.
2. 루트를 트리의 최상위로 놓고, 노드 펼침마다 `svn ls <url>`(신규 빌더,
   `remote_query` 부류)을 lazy 실행한다. 출력에서 `/`로 끝나는 항목이 디렉터리다.
3. **디렉터리만 표시한다** — 전환 대상은 디렉터리이므로 파일은 목록에서 뺀다.
4. 조회 결과는 다이얼로그 상태에 노드별로 캐시하고, 닫으면 폐기한다. 같은 노드
   재펼침은 캐시를 쓴다.

**UI**

- 기존 switch 다이얼로그 골격(오버레이 + 패널 + 행 element)을 확장한 트리 목록:
  들여쓰기 + 펼침 글리프(▸/▾), 로딩 중 행은 "조회 중…", 실패 행은 오류 문구.
- 현재 전환 위치 노드는 강조 표시하고, 트리를 그 경로까지 자동으로 펼쳐 둔다.
- 디렉터리 행 선택 + [전환] 버튼으로 실행. 현재 위치와 같은 URL이면 버튼 비활성.
- 인증 필요 시 ADR-003대로 프롬프트 없이 즉시 실패하며, 해당 노드에 "인증이
  필요해 조회하지 못했습니다"를 표시한다.

**검증 규칙 변경**

- `validate_svn_switch_target`의 허용 목록 대조를 제거한다. 안전장치는 이미 있는
  저장소 동일성 검증(`repos-root-url`/`repos-uuid` 일치, 실행 직전 네트워크
  조회)이 대신한다 — 브라우저가 루트에서 출발하므로 구조적으로도 같은 저장소만
  선택 가능하다.
- URL 형식 필터(`is_supported_svn_url`)는 유지한다.
- `svn_switch_targets` 필드: 문서 호환을 위해 **읽되 무시하고 보존**한다
  (2026-08-20 검수 확정). 후보는 전부 저장소 실조회로 얻는다.

**테스트**

- `svn ls` 빌더/파서: Apache 문서 계약 기반 fixture (기존 SVN fixture 관례,
  실측 아님을 `#` 주석으로 명시).
- 트리 상태(펼침/캐시/오류 행) 로직은 순수 함수로 분리해 단위 테스트.
- 실환경 SVN 검증은 기존 후속 항목 10(SVN 실측)에 `ls` 출력 형식 확인을 추가.
