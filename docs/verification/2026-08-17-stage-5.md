## 5. 알려진 한계와 후속 단계로 남긴 것

- **자식 단위 접근 실패 감지**: `vcs_file_probe`가 존재 부재와 접근 실패를 구분하지 않아 자식 하나의 `inaccessible` 판정을 실제로 만들 수 없다. 판정 규칙의 분기는 test로 고정해 두었고, 단계 2 실측(로컬 NTFS는 deny ACE로 속성 조회를 실패시킬 수 없음)까지 고려하면 실환경 영향은 작다. 계약 확장이 필요해지면 단계 6~7에서 다룬다.
- 네트워크 드라이브와 실제 느린 경로는 이 호스트에서 재현 수단이 없어 미검증이다. 단계 8의 실 환경 검증 항목이다.
- 탐색 미리보기 dialog, 선택 UX, 스레드 배치와 진행 표시는 단계 6~7 범위다. 단계 5는 동기 API와 후보 데이터까지만 제공한다.
- `.git` 파일 내용(gitdir)을 읽어 worktree와 submodule을 구분하는 표시는 UI 요구가 생길 때 추가한다.

## 6. 단계 6 시작 전 차단 조건 (재고지)

`docs/handoff.md` 5장의 게이트에 따라, **단계 6 구현을 시작하기 전에 ADR-004 범용 스레드 메시지 구조의 설계안을 별도로 제시하고 사용자 승인을 받아야 한다.** 요구 자료는 다음과 같다: 범용 public C++ API 초안, message 및 envelope type 표, queue topology와 ordering·backpressure 계약, cancellation·timeout·late result·shutdown scenario, sequence diagram과 failure path, deterministic test 및 sanitizer 전략. 승인 전에는 message queue, dispatcher, thread bridge를 작성하지 않는다.
