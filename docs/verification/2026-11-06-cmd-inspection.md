# 배치 조회 취소 검증 (2026-11-06)

## 1. 범위

- 요청한 기존 안정화는 `0648390`으로 커밋했다(push 없음). 브랜치는
  `codex/luil-integration-shutdown`이다. 이 기록의 조회 취소는 그 뒤의 별도 변경이다.
- 구현 결정은 [ADR-008](../decisions/ADR-008-cancellable-cmd-target-inspection.md)이다.
  luil 핀 `077262e`와 단일 실행 파일 배포를 유지한다.

## 2. 구현

- 같은 exe의 숨은 모드가 파일 속성·열기·앞부분 읽기를 한다. 부모는 익명 공유 메모리·event·job으로
  실행을 관리하고 pipe reader thread나 동기 파일 API를 조회 worker에서 호출하지 않는다.
- cmd 조회만의 취소 token을 registry에 등록했다. 문서 교체·닫기·종료·5초 상한에서 실제 조회를
  취소한다. 끝난 조회의 늦은 답은 버린다. 취소·시간 초과·실패는 사용자 프로그램으로 이어지지 않는다.
- 원래의 순수 배치 검사 함수는 자식과 단위 검사에서 재사용한다. executor의 실제 파일 I/O 직접
  fallback은 없앴다. 보조 모드는 UI·앱 설정·렌더러를 시작하지 않고 mapping과 event만 상속한다.
- 이전 자식의 OS 회수가 남으면 같은 inspector가 추가 자식을 만들지 않는다. UNC 형식 exe에서
  보조 모드를 시작하지 않으며, 실행 파일은 로컬 설치를 전제로 한다.

## 3. 자동 검사

- 영향 범위 `[cmd_inspection],[function_buttons][s3]`: **31 case, 595 assertions 통과**.
- Debug 전체 CTest **1226개 중 통과 1223, 건너뜀 3, 실패 0**, 112.93초.
- Release 전체 CTest도 **1226개 중 통과 1223, 건너뜀 3, 실패 0**, 87.04초.
  건너뜀은 네트워크 test 미설정 두 건과 실제 SVN 미설치 한 건이다. 새 test case는 10개다.
- Debug·Release 빌드 경고 0, 소스 스타일 511개 파일·diff 공백 검사 통과.
  사용 설명서 HTML 생성·일치 검사도 h2 22개·h3 57개, 문제 0이다.
- 보조 프로세스에서 Unicode·공백·메타 문자가 든 경로, 상대 경로, 배치 findings를 확인한다.
- oplock으로 파일 열기를 붙잡은 채 취소와 시간 초과가 부모 호출을 반환시키는지 검사한다.
  취소 뒤 같은 inspector로 다음 읽기도 성공한다. 없는 loopback UNC share도 제한 안에 돌아온다.
- 문서 변경·타임아웃의 token 취소, 조회 실패 뒤 실행 금지, executor의 경계 주입·예외·취소를
  검사했다. 기존 worker 검사는 명시적 검사 대역을 주입하게 바꿨다.
- 로그: `build/cmd-inspection-{debug,release}-{build,ctest}.log`,
  `build/cmd-inspection-debug-final-build.log`, `build/cmd-inspection-targeted.log`.

## 4. 실제 앱: 끝나지 않은 파일 읽기

임시 배치 파일의 open을 Windows oplock으로 붙잡고 사용자 화면과 분리된 데스크톱에서 UIA로
조작했다. 파일 잠금은 앱·조회 자식과 별도 프로세스가 소유하며 검사가 끝날 때까지 해제하지 않는다.
신뢰 전 로컬 배치 사전 조회 단계이므로 사용자 배치는 실행하지 않았다.

| 경로 | 결과 |
| --- | --- |
| 이전 실행 파일 닫기 | 보조 자식 0개. 파일을 해제하기 전 2.5초 안에 부모가 끝나지 않았다. 해제한 뒤 끝났다. |
| 수정본 앱 닫기 | 보조 자식 1개를 확인했다. 파일을 풀기 전에 부모와 조회 자식이 종료됐다. |
| 수정본 문서 닫기 | 파일을 풀기 전에 문서가 닫혔고 뒤이은 앱 종료와 자식 정리도 완료됐다. |
| 수정본 5초 상한 | 실행하지 않았다는 로그 뒤, 첫 파일을 계속 잠근 상태에서 다른 배치 조회가 완료돼 신뢰 창이 떴다. 취소로 닫았다. 이후 부모·자식도 잠금 해제 전에 종료됐다. |

스크립트와 원문은 `build/cmd-inspection-uia/probe.ps1`, `before-close.log`, `after-close.log`,
`after-document.log`, `after-timeout.log`다. `after-timeout/timed-out.png`는 실제 캡처다.
실제 UNC 형식 조회는 loopback의 없는 share로 검사했고, 끝나지 않는 I/O는 oplock으로 결정적으로
재현했다. 외부 SMB 서버나 kernel 고장을 재현했다고 읽지 않는다. 사용자 설정·입력은 바꾸지 않았고
앱·보조 프로세스·oplock을 정리했다. 이 산출물은 build 아래에 있으며 커밋하지 않는다.

## 5. 한계와 후속

호출 worker의 반환과 OS의 완전한 I/O 회수는 구분한다. 지원하지 않는 드라이버나 영구 kernel I/O
정지에서도 자식 회수 시각을 보장하는 것은 아니다. 부모가 자식의 주소 공간을 공유하지 않고
자식을 무제한 늘리지 않도록 했다. 일반 파일·VCS 조회, 실제 사용자 프로그램의 네트워크 I/O,
store 교체 재시도는 이 변경의 대상이 아니다. 실제 전역 설정·음성 검수도 별도다.

```text
- 조회 전용 token을 등록하고 제한 시간·문서 교체·종료에서 실제 조회를 취소함

```
