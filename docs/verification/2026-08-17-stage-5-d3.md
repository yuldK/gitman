# 단계 5 `S5-D3` 검증 기록 - 2026-08-17

## 1. 결과

`project_registration_service`의 선택 등록을 구현했다. 선택 재검증, id 생성, 후보의 `project_definition` 변환, 문서 갱신과 단계 2 revision token을 통한 저장 충돌 보고다. fake store 기반 규칙 test 6개와 실제 `json_project_store`를 쓰는 통합 test 2개를 같은 구간에서 작성했다.

VS2022 Debug/Release와 VS2026 Debug build 및 전체 CTest가 각각 **436/436** 통과했다(이전 428 + 신규 8). VS2022 `/analyze` 무경고, aggregate format/style(247개 파일) 통과, VS2022 Debug 전체 suite 3회 반복 무결함이다. 발견 production 결함은 없다.

### 2.2 등록 규칙

- **부분 등록은 없다.** 빈 선택, 제외 후보, 종류 미판정, 상대 경로, 문서와의 중복, 선택 목록 안의 중복 중 하나라도 있으면 저장을 호출하지 않고 전체를 거부한다. fake store의 저장 호출 수 0으로 직접 단정했다.
- 정규화 값은 탐색 시점의 값을 믿지 않고 **등록 시점에 다시 해석한다.** 다른 문서로 등록되거나 오래된 값으로 중복 검사를 통과하는 것을 막는다.
- id는 디렉터리 이름 그대로, 충돌 시 `-2`부터 숫자 접미사다. 접미사가 붙은 이름끼리의 재충돌(`repo-2` 존재 시 `repo-2-2`)과 한글 이름도 test로 고정했다.
- `vcs_hint`는 탐색이 판정한 종류(`git`/`subversion`)를 기록한다.
- 저장은 `project_store::save`에 load에서 받은 revision token을 그대로 전달한다. 새 충돌 감지 장치를 만들지 않았다.
- 성공 시에만 갱신 문서와 새 revision을 돌려준다. 실패한 등록이 문서 상태를 바꿀 수 없다.

## 3. test 범위

| test | 확인 내용 |
| --- | --- |
| id 생성 | 그대로 사용, `-3` 진행, 한글 이름, `repo-2`의 재충돌 |
| 변환 규칙 | git·SVN 후보의 id, 표시 이름, 절대 경로, hint, `enabled`, 빈 `svn_switch_targets`. 기존 항목과 `settings` 보존 |
| id 유일성 | 문서의 기존 id와 같은 이름의 후보가 `repo-2`로 등록 (경로가 다르면 등록 자체는 허용) |
| 전체 거부 4종 | 제외 후보 혼입, 종류 미판정, 상대 경로, 빈 선택. **모두 저장 호출 0** |
| 중복 거부 2종 | 문서와의 중복, 선택 목록 안의 중복. 저장 호출 0 |
| 실제 round-trip | 실제 store로 등록 → 재load에서 항목 2개 확인, **unknown field(`custom_field`)와 `settings`의 알 수 없는 키(`future_key`) 보존** |
| 실제 저장 충돌 | load와 등록 사이의 외부 수정 → `concurrent_modification`으로 거부, **외부 수정본 원문 그대로 보존** |
| 진단 code 이름 | `registration_candidate_rejected` 안정성 |

통합 test는 실제 `win32::workspace_document_file_system`, 실제 `win32::make_project_path_resolver()`와 단계 2의 `json_project_store`를 그대로 사용한다. VCS 실행 파일은 필요 없다.
