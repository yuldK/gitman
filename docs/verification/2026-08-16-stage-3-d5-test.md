비밀 마스킹 규칙과 적용 지점을 검증하는 test만 작성했다. Catch2 test 10개를 추가해 전체 CTest가 125개에서 135개가 됐다. production code는 변경하지 않았다.

이번 구간에서 발견한 production 결함은 없다. 따라서 `S3-D5-FIX`는 사용자 확인 후 생략 대상이며, 그 뒤 `S3-V1` 단계 3 최종 검증만 남는다.

## 2. 추가한 test

### 2.1 `tests/secret_masking_tests.cpp` (9개)

모든 단정은 `check_masked`를 거치며, 이 helper는 기대값 비교와 함께 **결과를 다시 마스킹해도 같은지**(idempotency)를 매번 확인한다.

| test | 확인 내용 |
| --- | --- |
| URL userinfo | 비밀번호 포함 URL, `svn+ssh` URL, 사용자 이름 없는 token URL, 메시지 안의 URL, 한 줄에 있는 URL 두 개 |
| userinfo 없는 URL | 일반 URL, query와 fragment가 있는 URL, `://`가 없는 SSH 축약 형태(`git@github.com:owner/repo.git`)는 그대로 유지 |
| 자격 증명 option | 공백 구분, `=` 구분, `--private-token=`, `--access-token`, 인용된 값, 값이 없는 `--password` |
| 접두어만 같은 option | `--password-from-stdin`, `--passwordless`, `--no-password=keep`는 그대로 유지 |
| 헤더와 Basic | `Authorization:`, 소문자 `authorization:`, `PRIVATE-TOKEN:`, `x-access-token:`, 단독 `Basic`, 8자 미만 `Basic auth` |
| token 접두어 | `ghp_`, `github_pat_`, `glpat-`, 한 줄의 접두어 두 개, 값 없는 `ghp_`, 다른 단어 안의 `xghp_abcdefg` |
| 일반 출력 | 빈 문자열, 영문 상태 메시지, 한글과 경로, 변경 통계 줄, commit hash 줄은 변형되지 않음 |
| 복수 비밀 | 한 줄에 URL, option, token이 함께 있어도 모두 가려짐 |
| 보수적 경계 | `secret_mask` 값 확인과 함께, 자격 증명에 붙은 구두점이 함께 가려지는 문서화된 동작을 고정 |

마지막 test는 `[--password=hunter2]`가 `[--password=***`가 되는 동작을 명시적으로 고정한다. 의도한 계약임을 코드에 남겨, 이후에 우연히 바뀌면 test가 알려 준다.

### 2.2 `tests/win32_process_runner_tests.cpp` 추가분 (1개)

자식에게 URL과 `--password=` 인자를 실제로 넘겨 end-to-end 적용을 확인한다.

- 기록된 `masked_command_line`에 비밀 문자열이 남지 않고 `https://user:***@example.com/repo.git` 형태가 포함된다.
- 출력 레코드 두 개 모두에서 비밀이 사라진다.
- 동시에 자식이 받은 argv는 원본 그대로였음이 첫 레코드의 URL 구조로 확인된다. 마스킹이 실행 인자가 아니라 기록에만 적용된다는 계약이다.
