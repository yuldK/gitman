# 4단계 (a) — SVN 훅

날짜: 2026-09-10 · 설계: `docs/custom-commands-and-svn-hooks-design.md` (H) ·
지시: 2026-09-10 사용자 요청 · 요구사항: REQ-021

## 1. 변경 요약

| 항목 | 반영 |
| --- | --- |
| TortoiseSVN 훅 재사용 | `HKCU\Software\TortoiseSVN`의 `hooks` 값을 읽어 update 계열 훅을 그대로 실행한다 |
| 자체 훅 | 전역·문서의 `commands.svn_hooks.hooks`를 목록 순서대로 순차 실행한다 |
| 지점 | update·switch의 `start_update` · `pre_update` · `post_update` |
| 실패 | pre 계열이 0이 아닌 코드로 끝나면 본 명령을 실행하지 않는다 (`hook_rejected`) |
| 인자 | TortoiseSVN 훅은 규약대로 임시 파일, gitman 훅은 `GITMAN_*` 환경 변수 |

## 2. 구현 경계

- **레지스트리는 platform만 읽는다.** `vcs_tool_environment`에 설치 폴더와 `hooks`
  값 원문을 실어 infrastructure로 넘긴다. 해석(`parse_tortoise_svn_hooks`)과 선택
  (`select_tortoise_svn_hook`)은 순수 함수라 레지스트리 없이 test한다. 32비트로
  빌드해도 64비트 뷰를 보도록 `KEY_WOW64_64KEY`를 준다.
- **record 경계를 방어적으로 읽는다.** 현재 판은 여섯 줄, 옛 판은 다섯 줄이다
  (ticket #482). 여섯 번째 토큰이 아는 종류 이름이면 그것을 다음 record의 시작으로
  본다. 종류 이름이 아닌 줄이 나오면 한 줄씩 밀며 다시 맞춘다.
- **commit·lock 계열 훅은 버린다.** gitman이 그 작업을 하지 않는다.
- **작업 복사본 속성 훅(`tsvn:preupdatehook` 등)은 읽지 않는다.** TortoiseSVN은
  그쪽을 승인 대화상자로 막는데 gitman에는 승인 개념이 없다. 설계 H3의 결정이다.
- **임시 파일 계약을 새로 뒀다.** `application/temp_file_writer`이고 구현은
  `platform/win32/win32_temp_file_writer`다. 붙이지 않은 조립에서는 TortoiseSVN
  훅만 건너뛴다 — 규약을 어긴 채 실행하면 남의 스크립트가 엉뚱한 인자를 받는다.
- **`start_update`는 사전 검사 앞이다.** 훅이 작업 트리를 건드리면 그 결과가 검사에
  반영되어야 한다. switch도 같은 자리에서 돈다 — 대상이 나중에 거부되어도 도는
  것은 TortoiseSVN의 start 훅과 같다 (대화상자 전에 돈다).
- **post는 성패와 관계없이 돈다.** 실패했으면 그 요약이 `GITMAN_HOOK_ERROR`와
  TortoiseSVN의 ERROR 파일에 들어간다. post 훅이 실패해도 경고만 남긴다 — 이미
  실행된 명령을 되돌릴 수 없다.
- **명령줄을 이름과 인자로 쪼갠다.** TortoiseSVN은 명령줄 문자열을 그대로
  `CreateProcess`에 넘기지만 gitman의 runner는 실행 파일과 인자 배열을 요구한다.
  이름만 적힌 프로그램(`python`)은 `.exe`를 붙여 PATH에서 찾는다.

### 알려진 차이 (설계 H5)

| TortoiseSVN | gitman |
| --- | --- |
| `show` (콘솔 창 보이기) | 지키지 않는다. runner가 `CREATE_NO_WINDOW`를 고정한다. 출력은 카드 로그로 간다 |
| `wait=false` | 프로세스는 기다리되 종료 코드를 판정에 쓰지 않는다. TortoiseSVN도 그 경우 오류를 보고하지 않으므로 결과는 같다 |
| `enforce` | 읽어만 둔다. gitman에는 "훅 없이 다시 시도" 경로가 없다 |
| `post_update`의 RESULTPATH | 빈 파일을 넘긴다. gitman은 `svn update` 출력을 경로 목록으로 파싱하지 않는다 |
| DEPTH · REVISION | 늘 `3`(infinity)와 `HEAD`다. gitman은 `--depth`도 리비전도 지정하지 않는다 |

## 3. 검증

빌드·test 환경: Visual Studio Community 2026 (18.9.12120.119, MSVC 19.51),
CMake 4.4.2, preset `vs2026-tests` / `vs2026-tests-release`.

### 새 TEST_CASE

| 파일 | TEST_CASE |
| --- | --- |
| `tests/svn_hook_tests.cpp` | TortoiseSVN hook records are read six lines at a time |
| `tests/svn_hook_tests.cpp` | An older five line record and unrelated hook types are tolerated |
| `tests/svn_hook_tests.cpp` | A hook is chosen by the closest matching path |
| `tests/svn_hook_tests.cpp` | A stored command line splits into a program and arguments |
| `tests/svn_hook_tests.cpp` | Gitman hooks run in order and a failing pre hook blocks the operation |
| `tests/svn_hook_tests.cpp` | A failing post hook warns but does not block |
| `tests/svn_hook_tests.cpp` | A hook outside the path pattern does not run |
| `tests/svn_hook_tests.cpp` | TortoiseSVN hooks receive the parameter files in order |
| `tests/svn_hook_tests.cpp` | TortoiseSVN hooks are skipped when parameter files cannot be made |
| `tests/svn_hook_tests.cpp` | Turning off TortoiseSVN reuse leaves its hooks alone |
| `tests/svn_hook_tests.cpp` | A failing start hook stops the update before any svn command |

| 항목 | 결과 |

| `cmake --build --preset vs2026-tests-release` | 성공, 경고 없음 |

### 검증하지 않은 것

- **이 호스트에 TortoiseSVN도 SVN CLI도 설치되어 있지 않다.** 레지스트리 읽기와
  실제 `svn.exe` 실행 경로는 미검증이며, 이는 SVN 전반에 대한 기존 보증 범위와
  같다 (ADR-003, `svn_repository_provider` 헤더 주석). 훅 선택 규칙과 인자 구성은
  값 test로 덮었다.
- 실제 훅 스크립트를 띄우지 않았다. `fake_process_runner`로 "무엇을 실행하려
  했는가"를 본다.
- Visual Studio 2022 toolchain, Debug 구성, `/analyze`는 최종 단계로 미뤘다.

## 4. 남은 수동 검수

- TortoiseSVN이 설치된 컴퓨터에서 설정 화면으로 `pre_update` 훅을 등록하고 gitman의
  업데이트를 눌러 그 훅이 도는지 확인한다.
- 훅이 0이 아닌 코드로 끝났을 때 `svn update`가 실행되지 않고 카드에 "훅이 실패해
  작업을 시작하지 않았습니다"가 뜨는지 확인한다.
- `post_update` 훅이 받은 ERROR 파일에 실패 요약이 들어 있는지 확인한다.
- `%TEMP%\gitman-hooks`에 파일이 쌓이지 않는지(실행 뒤 지워지는지) 확인한다.
- `commands.svn_hooks.use_tortoise_svn`을 끄면 TortoiseSVN 훅이 돌지 않는지
  확인한다.
