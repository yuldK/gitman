# 단계 6 `S6-D1` 검증 기록 - 2026-08-17

## 1. 결과

ADR-005의 범용 메시지 component를 구현했다. `messaging::channel<T>`(MPSC FIFO), `messaging::latest_slot<T>`(최신값 병합), envelope, 통계와 debug consumer thread ownership assert다. 계약 test 17개를 작성하고 같은 test를 `/fsanitize=address`로도 빌드해 실행하는 ASan target을 추가했다.

- VS2022 Debug/Release, VS2026 Debug 전체 CTest 각각 **471/471** (이전 437 + messaging 17 + ASan 중복 17)
- Release의 ASan test 17개는 **실제 AddressSanitizer로 계측되어 실행**된다 (`-L asan`)
- VS2022 Debug 3회 반복 무결함, `/analyze` 무경고, format/style(257개 파일) 통과

발견 production 결함은 없다. 개발 중 구성 문제 3건(test lambda의 닫는 중괄호 style, ASan의 C5072 debug 정보 경고, vcpkg Catch2와의 STL 컨테이너 주석 LNK2038 및 ASan runtime DLL 배치)을 같은 구간에서 해소했다.

## 3. ASan 구성의 결정

- messaging은 header-only라 별도 실행 파일 하나만 `/fsanitize=address`로 컴파일해도 component 전체가 계측된다. 전체 빌드를 ASan으로 만들 필요가 없다.
- Debug 구성의 `/RTC1`과 ASan이 충돌하므로 **Debug가 아닌 구성에서만** ASan을 켠다. 검증은 Release로 실행하며 Debug에서는 같은 test가 비계측으로 한 번 더 도는 무해한 중복이다.
- C5072(기호 없음) 경고에 따라 이 target만 Release에서도 `/Zi`와 `/DEBUG`를 켠다.
- vcpkg의 Catch2는 ASan 없이 빌드되어 STL 컨테이너 주석 불일치(LNK2038)가 나므로 이 target은 `_DISABLE_STRING_ANNOTATION`/`_DISABLE_VECTOR_ANNOTATION`으로 컨테이너 주석을 끄고 heap 검사를 사용한다.
- 최신 MSVC의 ASan runtime은 동적 DLL뿐이라 configure 시점에 cl.exe 디렉터리에서 `clang_rt.asan_dynamic-x86_64.dll`을 찾아 실행 파일 옆에 복사한다.
