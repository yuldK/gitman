# 단계 3 `S3-D5-CODE` 검증 기록 - 2026-08-16

## 1. 결과

비밀 마스킹을 구현하고 출력 레코드와 기록용 명령줄에 적용했다. 단계 3의 마지막 production 구간이다.

VS2022 Debug/Release와 VS2026 Debug build가 통과했고 기존 전체 CTest가 각 125/125 통과했다. VS2022 `/analyze`는 경고 없이 통과했다. 새 test source는 작성하지 않았고, 저장소 밖 임시 프로그램으로 26개 항목을 수동 확인했다. 상세는 5장에 있다.

## 2. 구현 범위

### 2.1 마스킹 규칙

`src/infrastructure/secret_masking.h/.cpp`는 단일 통과 scanner다. `std::regex`는 대용량 출력에서 성능과 스택 위험이 있어 사용하지 않았다.

| 규칙 | 처리 |
| --- | --- |
| URL userinfo | `scheme://user:secret@host`는 사용자 이름을 남기고 비밀만 가린다. `scheme://token@host`처럼 사용자 이름 없이 들어간 값은 대개 token이므로 전체를 가린다. |
| 자격 증명 option | `--password`, `--pass`, `--token`, `--access-token`, `--private-token`, `--auth-token`의 값을 가린다. `=` 형태와 공백 구분 형태를 모두 처리하고 명령줄 인용이 남아 있으면 따옴표 안쪽만 가린다. |
| 헤더 형태 출력 | `Authorization:`, `PRIVATE-TOKEN:`, `x-access-token:` 뒤의 값을 줄 끝까지 가린다. scheme과 자격 증명이 함께 있기 때문이다. |
| `Basic` 자격 증명 | `Basic` 뒤에 8자 이상의 base64 문자열이 오면 가린다. |
| token 접두어 | `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`, `glpat-` 뒤에 값이 붙으면 전체를 가린다. |

세부 계약은 다음과 같다.

- option과 token 이름은 단어의 처음에서만 인식한다. `--passwordless`와 `xghp_abc`처럼 다른 값의 일부인 경우는 건드리지 않는다.
- option 이름 뒤에 `=`나 공백이 오지 않으면 더 긴 다른 option으로 보고 넘어간다. `--password-from-stdin`이 그대로 남는다.
- 값이 없는 이름만 있는 경우(`ghp_`, 값 없는 `--password`)는 가리지 않는다.
- 규칙 목록을 한 파일의 배열로 모아 단계 4에서 provider별 인자를 확정할 때 확장하기 쉽게 했다.
- 이미 가려진 문자열을 다시 넣어도 결과가 같은 idempotent 연산이다.

### 2.2 적용 지점

| 대상 | 적용 위치 |
| --- | --- |
| 출력 레코드 | `process_output_pipeline::fill_text`에서 인코딩을 확정한 뒤 마지막에 적용한다. UTF-8 경로와 code page fallback 경로가 모두 지나가므로 어떤 인코딩으로 들어온 자격 증명도 sink에 도달하기 전에 가려진다. |
| 명령줄 기록 | `process_result::masked_command_line`에만 적용한다. 자식에게 넘기는 실제 명령줄은 원본 그대로다. |

`S3-D2-CODE`에서 실행용 명령줄과 기록용 값을 분리해 두었기 때문에 이번 변경으로 실행 인자가 바뀌지 않는다.

### 2.3 보수적 마스킹

값의 끝은 공백이나 줄 끝으로 판정한다. 따라서 자격 증명 바로 뒤에 붙은 구두점은 함께 가려질 수 있다. 예를 들어 `--password=hunter2]`는 `--password=***`가 된다.

비밀을 덜 가리는 것보다 주변 문자를 더 가리는 편이 안전하므로 이 동작을 유지한다.

## 5. 저장소 밖 수동 확인

임시 확인 프로그램으로 26개 항목을 검사했고 모두 통과했다. 각 항목은 결과를 한 번 더 마스킹해 idempotency도 함께 확인했다.

| 묶음 | 확인 항목 |
| --- | --- |
| URL | 비밀번호 포함, 사용자 이름 없는 token, userinfo 없는 URL, `svn+ssh` URL, 메시지 안의 URL |
| option | 공백 구분, `=` 구분, 인용된 값, `--password-from-stdin`, `--passwordless`, `--private-token=` |
| 헤더와 Basic | `Authorization:`, `PRIVATE-TOKEN:`, 단독 `Basic`, 8자 미만 값 |
| token | `ghp_`, `github_pat_`, `glpat-`, 값 없는 접두어, 다른 단어 안의 접두어 |
| 무변경 | 일반 출력, 한글과 경로가 섞인 출력, 빈 문자열 |
| end-to-end | 자식에게 URL과 `--password=` 인자를 넘겼을 때 기록된 명령줄과 출력 레코드 모두에서 비밀이 사라짐 |
| 성능 | 4 MB 출력이 863 ms에 65,574 레코드로 수집됨 |

## 6. 구현 중 검토 결과

- 마스킹을 인코딩 확정 이후에 적용하도록 순서를 정했다. code page fallback으로 복원한 텍스트에 자격 증명이 있어도 가려진다.
- option 이름 판정에서 접두어 충돌을 배열 순서로 해결하지 않고, 이름 뒤에 `=`나 공백이 오는지로 판정했다. 목록에 항목을 추가해도 순서에 의존하지 않는다.
- 4 MB 출력 기준으로 마스킹 도입 후에도 1초 미만이라 실용적인 비용임을 확인했다.
- 현재 알려진 production 결함은 없다. 전용 test는 체크포인트 분리 규칙에 따라 아직 작성하지 않았다.

## 7. 남은 제약

`S3-D5-CODE`까지 적용한 runner에는 계획에 명시된 미구현 항목이 없다. 기본 timeout, 기본 캡처 상한과 로캘 강제 여부는 명령별로 정할 사항이므로 단계 4에서 확정한다.
