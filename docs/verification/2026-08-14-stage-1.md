# 단계 1 빌드 및 품질 기준선 검증 기록

## 1. 검증 결론

단계 1 구현과 자동 검증을 완료했다. CMake 4.2.0, VS2022 v143와 VS2026 v145에서 정적 dependency와 애플리케이션 ABI를 일치시켰고, VS2022 Debug/Release 및 VS2026 Debug의 각 19개 CTest가 통과했다. install tree에는 `bin/gitman.exe` 하나만 생성됐다.

현재 상태는 **사용자 검수 대기**다. 단계 2는 사용자 승인 전까지 시작하지 않는다.

## 2. 범위

검증한 단계 1 범위는 다음과 같다.

- CMake preset, vcpkg manifest, 정적 runtime과 install
- 최소 Win32 창 및 platform adapter 경계
- Skia Direct3D와 CPU renderer, auto fallback
- custom caption skeleton, DPI-scaled layout과 hit test
- 엄격한 UTF-8 및 UTF-16 변환
- embedded Codicons font와 license 및 제3자 고지문
- Catch2, CTest, `/analyze`, clang-format과 source style 검사

Git/SVN provider, JSON 설정 저장소, 실제 카드 UI와 범용 thread message component는 구현하지 않았다.

## 6. Renderer와 Win32 경계

설치된 실행 파일을 숨김 smoke mode로 직접 실행한 결과다.

| 실행 | 종료 코드 |
| --- | --- |
| `gitman.exe --renderer=cpu --smoke-test` | 0 |
| `gitman.exe --renderer=auto --smoke-test` | 0 |
| `gitman.exe --renderer=auto --smoke-test --simulate-direct3d-failure` | 0 |
| `gitman.exe --renderer=direct3d --smoke-test` | 0 |

검증 호스트에서는 Direct3D D3D12 Skia surface가 실제로 초기화되고 frame을 제출했다. 강제 초기화 실패에서는 같은 drawing code를 CPU raster surface가 렌더링했다.

캡션 검수 의견 반영 후 보이는 CPU renderer 창을 캡처해 시스템 캡션이 사라지고 `source-control` Codicon이 icon slot 중앙에 표시되는 것을 확인했다. 실행 중 window style은 `WS_CAPTION` 없음, `WS_POPUP` 없음, resize/minimize/maximize style 유지 상태였다. system menu가 존재하고 maximize, minimize, close 위치의 `WM_NCHITTEST` 결과가 각각 `HTMAXBUTTON`, `HTMINBUTTON`, `HTCLOSE`인 것도 확인했다.

캡션 버튼 후속 검수에서는 일반 상태의 `chrome-maximize`와 최대화 상태의 `chrome-restore`를 각각 캡처해 glyph 전환을 확인했다. non-client button 입력을 보낸 결과 최소화, 최대화, 복원과 닫기가 모두 실제 window state에 반영됐다.

hover 후속 검수에서는 `WM_NCMOUSEMOVE`와 non-client leave 추적으로 세 caption button의 상태가 갱신되는 것을 확인했다. 144 DPI 실제 창에서 최소화와 최대화/복원은 중립 hover 배경 `(63, 63, 64)`, 닫기는 경고색 배경 `(196, 43, 28)`으로 렌더링됐고, 포인터를 client 영역으로 옮기면 기본 caption 배경 `(37, 37, 38)`으로 복귀했다. mouse message를 `DefWindowProcW`에도 전달한 상태에서 최대화 버튼 hover를 유지해 Windows 11 Snap Layout 팝업이 실제 표시되는 것도 캡처로 확인했다.

추가 자동 검증 항목은 다음과 같다.

- `auto`의 Direct3D 우선 및 CPU fallback 정책
- 명시적 `direct3d`와 `cpu` 정책
- 96/144/192 DPI caption button layout
- drag, minimize, maximize와 close hit test
- 한글, 공백과 emoji를 포함한 UTF-8 경로의 UTF-16 왕복
- 잘못된 UTF-8과 UTF-16 입력의 구조화된 오류
- Codicons font 및 두 license resource와 vcpkg 고지문 존재

## 8. 구현 중 발견하고 해결한 항목

1. VS2022와 VS2026이 함께 설치되면 vcpkg가 다른 Visual Studio instance의 STL을 선택할 수 있었다. generator major version에 맞는 설치본을 `vswhere`로 찾아 vcpkg에 전달하는 toolchain wrapper와 v143/v145 overlay triplet으로 해결했다.
2. 한글 Catch2 test case 이름은 Windows CTest filter 경계에서 코드페이지가 손상됐다. test identifier를 ASCII로 고정하고 테스트 본문과 프로젝트 문서는 한국어 설명 원칙을 유지했다.
3. `/analyze`가 `wWinMain`의 SDK SAL 계약 불일치를 검출했다. SDK 선언과 동일한 annotation으로 맞췄다.
4. Codex 샌드박스의 VS2026 MSBuild FileTracker 경로 조회는 권한 거부가 발생했다. 동일 명령을 승인된 호스트 환경에서 실행해 프로젝트 오류가 아님을 확인했다.
5. 사용자 화면 검수에서 시스템 캡션과 custom caption이 함께 그려지는 것을 확인했다. 표준 overlapped window로 OS 기본 배치를 받은 뒤 표시 전에 `WS_CAPTION`을 제거하고 frame을 재계산했다. resize, system menu와 minimize/maximize style은 유지해 custom caption 하나만 표시되며, `WS_POPUP` 전환으로 기본 창 배치를 잃지 않도록 했다.
6. caption의 repository Codicon이 앱 성격과 맞지 않고 고정 baseline에서 어색하게 정렬됐다. `source-control` glyph로 바꾸고 실제 glyph bounds를 기준으로 icon slot 중앙에 배치했다.
7. caption button의 수동 선 drawing을 `chrome-minimize`, `chrome-maximize`/`chrome-restore`, `chrome-close` Codicon으로 교체했다. non-client button 입력은 최소화, 최대화/복원과 닫기 시스템 명령에 직접 연결했다.
8. custom caption button에 시각적 hover가 없었다. non-client mouse move 및 leave를 추적해 일반 버튼과 닫기 버튼의 hover 색을 구분하고, client 진입, 비활성화와 크기 변경 때 상태를 해제하도록 보완했다.

## 9. 남은 수동 검수

자동 검증은 숨김 창과 caption geometry를 대상으로 했다. 사용자가 보이는 창에서 다음 Windows 11 동작을 확인해야 단계 1을 최종 승인할 수 있다.

- title bar drag와 가장자리 resize
- 최소화, 최대화, 복원, 닫기와 title bar double click
- `Alt+Space` system menu
- 서로 다른 DPI monitor 사이 이동과 Per-Monitor V2 재배치
- 고대비에서 caption button과 focus 식별 가능 여부

이 검수는 실제 카드 UI의 완성도 검수가 아니다. 단계 1의 custom caption skeleton과 네이티브 동작 보존 여부만 확인한다.
