# 검증 기록 - 단계 8 `S8-D4` Windows file association

## 1. 개요

- 날짜: 2026-08-19
- 대상: `S8-D4` (docs/stage-8-plan.md 6장)
- 진행 방식: 체크포인트 종료 시 검수 요청과 제안 커밋 메시지 첨부. 검증은 영향
  범위 테스트만 실행한다 (전체 CTest는 `S8-V1`)

## 2. 구현 내용

- **등록 값의 순수 계획** (`infrastructure/file_association`): ProgID
  `Gitman.VersionList`, `.version-list` 확장자 연결, 표시 이름, `DefaultIcon`
  (exe 자신, 공백 경로 대비 따옴표), `shell\open\command`(`"<exe>" "%1"`)를
  만드는 함수와, 제거 시 지울 subkey 목록(자식 먼저), 확장자 소유 판정
  (`owns_extension_link`)을 순수 함수로 분리했다.
- **Win32 registry adapter** (`platform/win32/win32_file_association`):
  **HKCU 범위만** 사용한다 (`HKCU\Software\Classes`, 관리자 권한 불요).
  - 등록은 멱등이며 기존 값을 덮어쓴다. 실제 root를 바꿨을 때만
    `SHChangeNotify(SHCNE_ASSOCCHANGED)`로 shell 캐시에 알린다.
  - 제거는 확장자 기본값이 **우리 ProgID일 때만** 연결을 지우고, 다른 앱이
    가져간 연결은 그대로 둔다. ProgID tree는 깊은 키부터 지우며 이미 없는 키는
    성공으로 본다 (멱등).
  - `file_association_registered`가 확장자 연결과 open command를 함께 확인한다.
  - root subkey를 주입할 수 있어 test는 `HKCU\Software\GitmanTest\...` 임시
    키에서 실측하고 실제 연결을 오염시키지 않는다 (stage-8-plan 5.4).
- **명령행 옵션**: `--register-file-association`·`--unregister-file-association`.
  창을 만들지 않고 수행한 뒤 종료 코드로 성패를 알린다 (스크립트 사용을 위해
  성공은 조용히, 실패만 dialog). 두 옵션을 함께 지정하면 파싱 오류다.
- **환경설정 dialog 버튼**: `연결 등록`·`연결 해제` 버튼이 UI thread 전용
  `ui_command`로 같은 adapter를 호출하고 결과를 시스템 dialog로 알린다
  (registry는 짧은 로컬 I/O이며 앱 상태와 무관해 logic을 거치지 않는다 —
  docs/ui-element-design.md 6.4의 ui_command 기준).
- `gitman_lib`에 advapi32 링크를 추가했다.

## 3. 테스트

새 test 7개 (전체 CTest 614 → **621**).

- 계획 값: ProgID·아이콘·따옴표 감싼 open command, 제거 목록의 자식 우선 순서,
  확장자 소유 판정.
- **실제 registry 실측** (임시 root): 등록 후 조회 가능, 반복 등록 멱등, 다른
  실행 파일 기준 미등록 판정, 빈 경로 거부. 제거 후 ProgID·확장자 키 소멸과
  반복 제거 멱등. **다른 앱이 가져간 확장자 연결은 제거 후에도 보존.**
  guard가 test 전후로 임시 tree를 지운다.
- 현재 실행 파일 경로 조회 (자기 자신).
- 명령행 flag 파싱과 동시 지정 거부.
- 환경설정 dialog 버튼의 `ui_command` 배선.

## 5. 비고

- 실제 연결(기본 root)의 등록, double-click 실행, 제거는 자동 test로 하지
  않는다 — 사용자 registry를 건드리기 때문이다. `S8-D5`/`S8-V1`의 수동 검증
  항목으로 실측한다: `bin\gitman.exe --register-file-association` →
  `.version-list` double-click으로 창이 열리고 문서가 활성화 →
  `--unregister-file-association` → 잔여물 없음.
- Explorer의 "연결 프로그램" 사용자 선택(UserChoice)은 앱이 건드릴 수 없는
  영역이다. 사용자가 다른 앱을 명시 선택한 경우 HKCU Classes 연결보다
  우선하며, 이는 Windows 정책상 정상 동작이다.
