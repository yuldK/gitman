# 검증 기록 - 단계 8 `S8-D2` 탐색 후보 선택 등록 dialog

## 1. 개요

- 날짜: 2026-08-19
- 대상: `S8-D2` (docs/stage-8-plan.md 6장)
- 진행 방식: 체크포인트 종료 시 검수 요청과 제안 커밋 메시지 첨부. 이 문서 제출
  후 사용자 승인·커밋을 기다린다

## 2. 구현 내용

- **toolbar에 탐색 버튼**(codicon `search`)을 추가했다 (REQ-004). 열린 문서가
  필요한 기능이라 문서가 없으면 비활성이다. 버튼은 UI thread 전용
  `ui_command::show_discovery_folder_picker`로 Win32 폴더 선택(`FOS_PICKFOLDERS`,
  시작 위치는 문서가 있는 폴더)을 열고, 고른 폴더를 `begin_discovery_intent`로
  logic에 보낸다.
- **탐색 dialog 상태**는 logic이 소유한다 (`discovery_dialog_state`). 열면서
  곧바로 `discover_projects` 작업을 제출하고 "탐색 중"을 표시한다. 탐색 요청에는
  기존 등록 항목과의 중복 판정을 위한 문서 사본과 **작업별 취소 token**이 실린다.
  dialog 취소·문서 교체·앱 종료가 진행 중 탐색을 취소한다 (단계 5 API의 자식
  경계 취소).
- **worker 실행**은 단계 5의 service를 그대로 조립한다. `discover_projects`는
  `discovery_service::discover_children`, `register_projects`는
  `project_registration_service::register_candidates`(all-or-nothing 원자 등록,
  revision 충돌 감지)다. scheduler는 두 작업을 문서 lane(0번)에 배정해 save와
  직렬화한다 — register는 같은 store 접근이라 필수이고 discover는 generate와
  같은 정책이다.
- **후보 표시**: 결정적 정렬 그대로의 행 목록에 체크박스, 종류 아이콘, 디렉터리
  이름, 제외 사유(한국어: 저장소 아님·bare 저장소·표식 충돌·링크·이미 등록됨·
  접근 실패)를 표시한다. 등록 가능 후보는 **기본 체크**이고 제외 후보는 비활성
  표시만 된다 (stage-8-plan 5.2). tooltip이 절대 경로를 보여 준다. 목록은
  스크롤·clip되며 휠이 목록을 스크롤한다.
- **등록**: `선택 등록` 확정 시에만 문서가 바뀐다. 성공하면 등록된 문서와 새
  revision을 활성 문서로 채택하되, **install_document를 거치지 않고 새
  프로젝트만 카드로 추가**해 기존 카드의 상태·로그·선택을 보존한다. 새 카드는
  곧바로 로컬 조회를 제출한다. 실패(저장 충돌 포함)는 dialog를 유지한 채 사유를
  표시하고 그대로 재시도할 수 있다.
- **자초 충돌 방지**: 일반 문서 저장이 진행 중이면 등록을 제출하지 않고 "잠시 후
  다시 시도" 안내를 표시한다. 등록 실행 중에는 dialog 닫기를 거부한다 — store
  저장은 취소할 수 없고 결과를 dialog가 보고해야 하기 때문이다. 등록 실행 동안
  dialog가 화면을 덮어 사용자의 다른 문서 수정 경로(순서 변경·설정 저장)도
  막히므로 채택 시 변경 유실이 없다.
- Esc 우선순위는 drag 취소 → 탐색 dialog → 환경설정 dialog → switch dialog →
  update overlay → 선택 해제다.
- 기존 `.version-list` 생성 기능(전량 등록)은 그대로 유지된다. 이 dialog는 이미
  열린 문서에 추가 등록하는 경로다.

## 3. 테스트

새 test 14개 (전체 CTest 596 → **610**).

- dialog 열기: 문서 사본·스캔 루트를 담은 discover 제출, 문서 없으면 미동작.
- 후보 도착: 등록 가능 후보만 기본 체크, 늦은 결과 폐기, 미완료 탐색의 한국어
  메시지와 확인 차단.
- toggle: 등록 가능 후보만 전환, 제외·범위 밖 무시, 전부 해제 시 확인 차단과
  늦은 확인 intent의 등록 미제출.
- 확인: 선택 후보만 담은 register_projects 제출(문서·revision 포함), 실행 중
  상태 전환. 일반 저장 진행 중에는 제출 대신 안내 표시.
- 등록 성공: 문서 채택, **새 카드만 추가**와 로컬 조회 제출, 기존 카드 상태
  보존, dialog 닫힘.
- 등록 실패: dialog 유지, 진단 메시지 표시, 재시도 가능.
- 취소: 진행 중 탐색의 token이 취소되고 dialog가 닫힘. 등록 실행 중에는 닫기
  거부.
- tree 배선: 행 클릭의 index toggle intent, 제외 행 비활성, 등록·닫기 버튼,
  toolbar 버튼의 `ui_command`와 문서 없음 비활성, Esc 취소, 휠의 목록 스크롤
  라우팅.

## 5. 비고

- 탐색·등록의 실제 filesystem 동작(junction, 접근 거부, 실제 store round-trip과
  저장 충돌)은 단계 5의 통합 test가 계속 보증한다. 이 체크포인트는 dialog 상태
  기계와 executor 배관을 추가했다.
- discover가 문서 lane에서 실행되므로 탐색이 오래 걸리는 동안 문서 저장이
  지연된다. `.version-list` 생성(generate)과 같은 기존 정책이며, 네트워크
  드라이브 같은 느린 경로의 실측은 단계 8의 알려진 제한 항목이다.
- 후보 행 element는 전량 생성하되 배치가 화면 밖 행을 숨긴다 (switch dialog와
  같은 정책).
