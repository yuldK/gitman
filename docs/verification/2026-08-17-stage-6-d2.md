### 2.1 핵심 결정

- **문서 load도 worker에 위임한다.** logic thread는 blocking 파일 I/O가 금지이므로(plan 3.8) `open_document` intent는 `load_document` 작업 제출로 끝난다.
- **초기 표시는 로컬 조회만, 활성 카드만이다** (plan 5.1). remote-first 판정은 refresh intent에서 `operation_kind::refresh`로 실행되며 worker가 로컬·원격 결과를 순서대로 두 event로 보고한다.
- **generation 정책은 logic 한곳에 있다.** 카드별 generation을 refresh마다 올리고, 오래된 세대와 삭제된 카드의 event를 폐기한다(ADR-004 검증 항목). 실행 중의 중복 refresh는 `refresh_queued` 하나로 병합해 마지막 event 후 새 세대로 이어 실행한다(plan 5.1의 병합).
- **layout은 view snapshot의 순수 함수다.** 렌더러와 input thread가 같은 `compute_layout`을 같은 snapshot으로 호출하므로 그리기와 hit test가 항상 일치한다. 화면에 걸치는 카드만 hit 영역을 만들어 카드 수백 개에서도 목록이 화면 크기에 비례한다.
- 카드 표시 상태 우선순위: disabled → running → loading → failed(조회 불가·오류) → warning(충돌·인증·오프라인·비교 대상 없음) → ready. 상태 정렬은 이 순서로 문제 카드를 위로 올린다.
- update/switch 버튼 영역은 `card_update_disabled`/`card_switch_disabled`로 배치만 하고 intent를 만들지 않는다 (단계 7 활성화).
