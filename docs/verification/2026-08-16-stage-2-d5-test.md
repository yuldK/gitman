# 단계 2 `S2-D5-TEST` 검증 기록 - 2026-08-16

## 1. 결과

`.verison-list` positional launch path production 계약을 대상으로 Catch2 test 4개를 추가했다. 경로가 없는 기존 시작, UTF-8 원문과 option 순서 보존, 대문자 확장자, 중복 positional path와 잘못된 확장자 거부를 검증했다.

VS2022와 VS2026 Debug build, 신규 test 4/4 및 전체 CTest 54/54가 모두 통과했다. 이번 체크포인트에서 `src/` production source는 변경하지 않았고, `S2-D5-FIX` 대상으로 기록할 production 결함도 발견하지 않았다. 사용자가 2026-08-16에 계속 진행을 지시해 test 검수를 승인했다.

## 2. 추가한 test 범위

| test | 검증 내용 |
| --- | --- |
| `Workspace launch path is optional` | renderer option만 전달한 기존 시작이 성공하고 `workspace_document_path`가 비어 있다. |
| `Workspace launch paths preserve Unicode and option ordering` | 한글과 공백이 포함된 경로 원문을 그대로 보존하며 path 전후의 renderer option을 처리하고 대문자 `.VERISON-LIST`도 허용한다. |
| `Duplicate workspace launch paths are rejected` | 알려진 option이 사이에 있어도 두 번째 positional path를 거부한다. |
| `Invalid workspace launch extensions are rejected` | `.json`, `.verison-list.bak`과 trailing space가 붙은 suffix를 작업공간 문서로 받아들이지 않는다. |

## 3. 변경 파일

- `tests/application_options_tests.cpp`
- 단계 상태, 변경 이력, 검증 및 인수인계 문서

`src/` production source, test CMake와 fixture는 변경하지 않았다.

## 4. 검증 결과

| 검증 | 결과 |
| --- | --- |
| VS2022 Debug build | 신규 launch path test를 포함해 통과 |
| 신규 launch path test subset | 4/4 통과 |
| `ctest --preset vs2022-debug --output-on-failure` | 전체 54/54 통과 |
| VS2026 Debug build | host 환경에서 신규 launch path test를 포함해 통과 |
| VS2026 신규 launch path test subset | 4/4 통과 |
| `ctest --preset vs2026-debug --output-on-failure` | 전체 54/54 통과 |
| clang-format dry run | 변경 C++ test source 통과 |
| line ending 및 source style | UTF-8 무 BOM, CRLF와 source style 검사 통과 |
| `git diff --check` 및 `git diff --cached --check` | 통과 |
| production source 변경 | 없음 |

build child process는 기존과 같이 중복 `PATH`/`Path`를 하나의 `Path`로 정규화했다. VS2026 build의 sandbox 실행은 기존 FileTracker 제한으로 `E_ACCESSDENIED`가 발생했으며, 같은 build를 host 권한에서 실행해 통과했다.

## 5. 작성 중 검토 결과

새 test source는 기존 application option test target에 추가했으므로 CMake와 fixture 변경이 필요하지 않았다. 정상 경로 검증은 filesystem 상태와 무관하게 parser가 전달받은 UTF-8 byte를 정확히 보존하는 계약에 집중한다.

이 test 체크포인트에서는 aggregate `gitman_format_check`의 기존 `utf8.cpp`, `win32_application.cpp`, `ui_theme.h` 위반을 범위 밖 기준선 보류 사항으로 유지했다. 이후 `S2-V1`에서 세 파일을 프로젝트 formatter로만 정렬해 aggregate 검사를 통과시켰다. 변경한 `application_options_tests.cpp`의 동일 formatter 직접 dry-run과 전체 source style 검사도 통과했다.

현재 알려진 production 결함과 `S2-D5-FIX` 후보는 없다.

## 6. 검수 완료

사용자가 2026-08-16에 계속 진행을 지시해 `S2-D5-TEST`를 승인했다. production 결함 후보가 없어 `S2-D5-FIX`를 수정 없이 생략하고 `S2-V1` 단계 2 최종 검증으로 진행했다.

`S2-V1` 결과는 `docs/verification/2026-08-16-stage-2.md`에 기록한다. 단계 2 최종 승인 전에는 단계 3을 시작하지 않는다.
