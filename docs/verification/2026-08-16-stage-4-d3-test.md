### 2.1 대상 선택 matrix

`select_git_remote_target`은 프로세스와 filesystem을 쓰지 않는 순수 함수라 규칙만 따로 단정한다.

| 조건 | 기대 |
| --- | --- |
| upstream이 remote를 가리킴 | `upstream`, tracking ref와 표시 이름 |
| branch 이름에 `/` 포함 | `origin/feature/a/b`를 나누지 않음 |
| `up`과 `up/stream`이 함께 있음 | **가장 긴 접두사**를 remote로 고름 |
| upstream이 local branch (`branch.x.remote = .`) | 다음 규칙으로 넘어가 현재 branch 이름을 씀 |
| `preferred_remote`가 있음 | `origin`보다 우선 |
| `preferred_remote`가 저장소에 없음 | 다음 규칙으로 진행하고 `preferred_remote_missing` 표시 |
| `origin`이 있음 / remote가 하나뿐 | 각각 `origin`, `only_remote` |
| remote가 여럿인데 좁혀지지 않음 | `ambiguous_remote`, **대상을 만들지 않음** |
| remote 없음 / detached / branch 미상 | `no_remote`, `detached_head`, `no_branch` |

### 2.2 명령과 순서

`fake_process_runner`가 기록한 요청으로 단정한다.

- 정상 경로에서 요청이 정확히 4개이고 순서가 `remote` → `fetch` → `rev-parse` → `rev-list`다.
- fetch 인자가 `fetch --prune -- origin`이고 마지막 값이 upstream이 가리키는 remote다.
- ref 확인 인자가 `rev-parse --verify --quiet refs/remotes/origin/main`이며 **`--`가 없다**. `rev-parse`의 `--`는 뒤의 값을 경로로 만들어 확인이 항상 실패한다.
- 차이 계산 인자가 `rev-list --left-right --count HEAD...<ref>`다.
- fetch만 `remote_query` 한도(120초)를 쓰고 나머지는 30초다.

**네트워크를 쓰기 전에 끝나는 경로**를 요청 수로 직접 단정한다.

| 조건 | 요청 수 |
| --- | --- |
| 도구 부재, 로컬 미준비, 경로 소멸, detached | 0 |
| remote 없음(`local_only`), 대상 모호 | 1 (`remote`까지) |
| fetch 실패 | 2 |
| tracking ref 없음, 커밋 없음 | 3 |

### 2.3 실패 분류

같은 실패의 영어 출력과 한국어 출력이 같은 분류를 내는지 쌍으로 단정한다.

| stderr 신호 | 분류 |
| --- | --- |
| `Could not resolve host` (영어) / `Failed to connect ... port 443`이 섞인 한국어 문장 | `offline` |
| `Permission denied (publickey)` (영어) / 같은 문구가 섞인 한국어 문장 | `authentication_required` |
| `https://...` + `The requested URL returned error: 403` | `authentication_required` |
| 어느 신호에도 없는 한국어 실패 문장 | `error` |
| `timed_out` 완료 사유 | `offline`과 `process_timed_out` 진단 |
| 취소 | `unknown`과 `process_cancelled` 진단, 원격 확인 시각 없음 |

### 2.4 실패해도 지우지 않는 값

fetch가 실패한 경우 직전 로컬 비교(`comparison_source::local`), ahead 수, 작업 트리 상태와 **이전에 성공한 `remote_checked_at`이 그대로 남는지**를 단정한다. 반대로 `remote_target_missing`으로 판정한 경우에는 ahead/behind와 비교 대상을 지우는지 단정한다. 유효하지 않은 비교를 남기면 카드가 잘못된 수를 계속 보여 준다.

### 2.5 통합 test

실제 `git.exe`와 로컬 bare 저장소만 사용한다. 네트워크에 접근하지 않는다.

| test | 확인 |
| --- | --- |
| 동기 상태 | `up_to_date`, `comparison=remote`, `origin/main`, 원격 확인 시각, 진단 없음 |
| ahead / behind / diverged | 한 test에서 세 저장소를 만들어 각각 1/0, 0/1, 1/1 |
| remote 없는 저장소 | `local_only`, 원격 확인 시각 없음 |
| 원격에 없는 local branch | `remote_target_missing`, fetch는 성공했으므로 확인 시각은 남음 |
| 도달 불가 URL(`http://127.0.0.1:1`) | `offline`, 직전 로컬 비교와 작업 트리 상태 보존 |
| 비ASCII 왕복 | Git이 되돌려 준 `없는 브랜치 😀`가 그대로 도착 |

`behind`와 `diverged`는 원격을 건드리지 않고 clone을 `reset --hard HEAD~1`로 되돌려 만든다. 준비가 결정적이고 원격 상태를 공유하지 않는다.

## 3. 한국어 Git 출력 인코딩 실측 (계획 4.10 및 11장 항목)

계획은 "한국어 Git 출력의 실제 인코딩 실측을 `S4-D3-TEST`에서 기록한다"를 남겼다. 이 호스트에서 실측한 결과는 다음과 같다.

| 항목 | 값 |
| --- | --- |
| 시스템 ANSI code page (`HKLM\...\Nls\CodePage\ACP`) | **949** |
| Git | Git for Windows 2.52.0 |
| 번역 catalog | **없음.** `share/locale` 디렉터리가 설치되어 있지 않다 |
| `LANGUAGE=ko`, `LC_ALL=ko_KR.UTF-8`, `LC_ALL=ko_KR.CP949`, `LANG=ko_KR` | 모두 영어 메시지. 바이트 수까지 동일 |
| 비ASCII 내용(branch 이름)의 인코딩 | **UTF-8**. `없는브랜치` → `EC 97 86 EB 8A 94 EB B8 8C EB 9E 9C EC B9 98` |

결론은 두 가지다.

1. 이 호스트의 Git은 번역본이 없어 메시지가 항상 영어다. 다른 호스트에는 번역본이 설치될 수 있으므로 **오류 분류는 계속 로캘 독립 신호만 사용해야 한다.** 이 실측은 분류 전략을 바꿀 근거가 되지 못한다.
2. Git이 되돌려 주는 비ASCII 내용은 활성 code page가 949인 환경에서도 UTF-8이다. `active_code_page_fallback`은 유효한 UTF-8 레코드를 건드리지 않으므로 그대로 통과한다. 이 왕복을 통합 test로 고정했다.

## 6. test 작성 중 발견한 것

production 결함은 없다. 다만 test를 쓰면서 두 가지를 확인했다.

1. **HTTP 상태 신호는 같은 텍스트에 `http`가 있어야 분류된다.** 처음에 `fatal: unable to access: The requested URL returned error: 403`처럼 URL을 뺀 문장을 test 데이터로 썼더니 `error`로 분류되어 test가 실패했다. `S4-D1-CODE`가 `branch 404` 같은 출력의 오탐을 막으려고 의도적으로 넣은 조건이며 실제 Git 메시지에는 항상 URL이 들어 있다. test 데이터를 실제 형태로 고쳤고 production은 그대로 두었다.
2. `gitman_source_style`의 "닫는 중괄호는 자기 줄에" 규칙과 clang-format의 200자 줄 합치기가 표 형태 test 데이터에서 다시 충돌했다. `S4-D2-TEST`와 같은 방법(값을 짧게 하거나 지역 별칭을 둠)으로 두 검사를 모두 만족시켰다.

## 7. 다음 구간

발견 결함이 없으므로 사용자 확인 후 `S4-D3-FIX`를 생략하고 `S4-D4-CODE`로 넘어간다. `S4-D4-CODE`는 SVN 명령 조립, `info --show-item`·비verbose `status`·`svnversion` 파서, 로컬 및 원격 상태와 mixed revision·switched 판정이다.

이 호스트에는 SVN이 설치되어 있지 않다. 계획 8.4대로 파서와 명령 조립은 고정 fixture와 fake runner로 검증하고 실제 `svn.exe` 경로는 미검증으로 남긴다.
