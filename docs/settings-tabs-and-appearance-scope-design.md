# 환경설정 탭 구조 · 외양의 문서 특수화 · 창 배치 범위 · 덮어씀 배지 설계

상태: **구현 완료** (2026-08-22 작성·구현. 사용자 지시로 검수 없이
`feature/settings-tabs-and-window-scope` 브랜치에서 체크포인트마다 커밋하고
마지막에 전역 test를 실행한 뒤 한 번에 보고한다)

2026-08-22 사용자 요구 4건의 설계를 기록한다.

| 항목 | 요구 |
|---|---|
| S1 | 환경설정 dialog를 섹션으로 계층화하고 섹션마다 탭을 둔다. 설정이 더 늘어나도 견뎌야 한다 |
| S2 | 테마와 키 컬러도 전역/문서 특수화로 나눈다. 키 컬러가 20개 규모로 늘어나므로 지금의 한 줄 나열로는 담기지 않는다 |
| S3 | 앱 단위 창 배치는 **문서를 열지 않은 경우에만** 유지한다. 문서를 열면 그때부터는 문서의 배치를 따르고 앱 단위로 기록하지 않으며, 문서를 여는 순간의 배치를 앱 설정에 저장한다 |
| S4 | `덮어씀` 배지가 얄팍하다. 세부 항목 바로 옆에 약간의 여백만 두고 배지를 붙인다 |

## S1. 탭과 섹션

### S1.1 현황

`settings_dialog_element`가 460×544 panel 하나에 행 8개를 세로로 쌓는다. 행은
`draw_row(index, label, value, placeholder)`로 그려지고, 컨트롤(찾아보기·토글·
세그먼트·스와치)은 `arrange`가 `children()[n]`의 고정 index와 행 번호로 좌표를
계산한다. 행이 하나 늘 때마다 panel 높이와 index 계산이 함께 바뀌는 구조라
항목이 더 늘어나면 유지되지 않는다.

### S1.2 결정: 탭 → 섹션 → 항목의 3단 구조를 자료로 기술한다

행 번호와 자식 index로 배치하던 것을 **자료(모델)로 기술하고 순회로 배치**한다.
element는 모델을 읽어 그리기만 하므로 항목이 늘어도 배치 코드는 그대로다.

```
panel
├─ 제목 줄               환경설정 (문서) / (전역)
├─ 좌측 탭 rail          도구 · 작업 · 외양 · 시스템
├─ 내용 영역             [섹션 제목] → [항목] → [항목] → [섹션 제목] → …
└─ 아래 버튼 줄          저장 · 취소
```

탭 구성이다. 항목은 지금 있는 8개 + 파일 연결 2 버튼을 나눈 것이고, 새 설정은
해당 탭의 섹션에 한 줄로 추가된다.

| 탭 | codicon | 섹션 | 항목 |
|---|---|---|---|
| 도구 | `tools` | 실행 파일 | Git 실행 파일, SVN 실행 파일 |
| | | 조회 | 상태 확인 제한 시간 |
| 작업 | `sync` | 업데이트 | 업데이트 시 submodule 갱신 |
| | | 상태 확인 | 로컬 변경을 상관하지 않음 (SVN) |
| | | 로그 | 로그를 문서 폴더에 파일로 남김 |
| 외양 | `symbol-color` | 테마 | 테마 |
| | | 키 컬러 | 키 컬러 |
| 시스템 | `link` | 파일 연결 | `.version-list` 연결 (등록·해제 버튼) |

- 탭은 **왼쪽 세로 rail**이다. 가로 탭과 달리 탭이 늘어도 글자가 줄지 않고,
  내용 영역의 세로 공간을 탭 줄에 내주지 않는다.
- 선택된 탭만 `accent_soft` 바탕과 `accent_emphasis_fg` 글자를 갖는다(테마
  세그먼트와 같은 규칙).
- 탭 전환은 dialog 상태만 바꾸는 intent다 — 초안(저장/취소)과 무관하다.
  탭을 옮겨도 다른 탭에서 고친 초안은 유지된다(초안은 dialog 단위다).

### S1.3 치수와 배치 규칙

| 값 | 논리 픽셀 |
|---|---|
| panel 너비 | 600 |
| panel 높이 | 탭별 내용 높이의 **최댓값**으로 빌드 시점에 정한다 (아래) |
| padding | 14 |
| 제목 줄 높이 | 34 |
| 탭 rail 너비 / 행 높이 | 132 / 32 |
| rail과 내용 사이 간격 | 14 |
| 섹션 제목 높이 (구분선 포함) | 26 |
| 항목 높이 (기본) | 48 |
| 아래 버튼 줄 높이 | 28 + padding |

- 항목 높이는 항목 종류가 정한다. 색 동그라미 항목만 줄 수에 따라 늘어난다
  (S2.4). 다른 항목은 기본 높이다.
- **panel 높이는 탭마다 다르면 탭을 옮길 때 창이 튀므로** 네 탭의 내용 높이
  중 가장 큰 값으로 고정한다. 색 목록이 늘어 외양 탭이 커지면 panel도 함께
  커진다 — 스크롤 막대를 두지 않아도 20색 규모까지 담긴다.
- 화면보다 커지면 기존 규칙대로 slot 크기로 잘린다(모든 dialog와 같다).

### S1.4 영향 범위

`app_messages`(+`settings_tab`·+`select_settings_tab_intent`),
`view_snapshot`(`settings_dialog_view`에 탭 상태), `logic_controller`
(dialog 상태에 `active_tab`, 핸들러 1개), `ui_element`(+`settings_tab_item`),
`settings_dialog_element`(전면 재작성), `settings_dialog_tests`.

## S2. 외양의 전역/문서 특수화

### S2.1 현황

`app_settings.appearance`(theme, accent_id) 하나뿐이고, 환경설정의 외양 2행은
문서 모드에서도 앱 설정을 편집한다(`(전역)` 표기, 배지 없음). 색 동그라미는 행
오른쪽에 한 줄로 나열되어 5개까지만 들어간다.

### S2.2 결정: 문서에 `appearance` override object를 둔다

다른 설정과 같은 계층(앱 전역 값 + 문서 override)을 외양에도 적용한다. 다만
외양은 `workspace_settings`(조회·실행에 쓰이는 값)와 성격이 달라 **별도
object**로 둔다 — 앱 설정 JSON의 `appearance`가 이미 `settings` 밖에 있고,
문서에서도 같은 이름·같은 모양이어야 읽는 사람이 헷갈리지 않는다.

```jsonc
// .version-list — 정의한 키만 남는다
{
    "settings": { /* … */ },
    "appearance": { "theme": "dark", "accent": "blue" }
}
```

- 도메인: `appearance_overrides { std::optional<theme_preference> theme;
  std::optional<std::u8string> accent_id; }`와
  `apply_overrides(const appearance_settings&, const appearance_overrides&)`.
- `workspace_document.appearance`가 이 override를 담는다. 파서는 알 수 없는
  값에 경고 진단 하나를 남기고 그 키를 정의되지 않은 것으로 둔다(앱 설정의
  기존 규칙과 같다). 저장은 `settings`와 같은 규칙이다 — 정의된 키만 쓰고,
  정의를 거둔 키는 지우며, 알 수 없는 키는 보존한다.
- logic의 `effective_appearance()`가 `view_snapshot.appearance`를 채운다.
  UI thread의 해석(고대비 > 명시 > 시스템)은 그대로다.

### S2.3 편집 규칙

다른 설정과 같다 — **문서가 열려 있으면 문서 override를, 없으면 전역 값을
편집한다.** 문서 모드에서 테마·색을 고르면 그 항목이 문서에 정의되고 `덮어씀`
배지가 붙는다. 배지를 누르면 정의가 사라져 앱 설정을 따른다.

외양 항목은 지금처럼 **즉시 반영·저장**한다(`저장`/`취소` 초안에 넣지 않는다).
색은 눌러 보고 고르는 항목이라 미리 보기가 곧 값이어야 한다. 따라서 문서 모드의
외양 배지도 초안이 아니라 문서를 직접 고치고 저장을 예약한다.

### S2.4 색 목록의 배치: 줄바꿈 격자

색 동그라미를 항목 값 줄 아래의 **격자**로 놓는다. 한 줄에 들어가는 개수는
내용 너비가 정하고, 넘치면 다음 줄로 내려간다. 항목 높이는 줄 수로 계산한다.

| 값 | 논리 픽셀 |
|---|---|
| 동그라미 지름 | 22 |
| 간격 | 8 |
| 격자 위 여백 | 6 |

`assets/accents.json`은 20색으로 늘린다(요구 S2). 스키마와 빌드 시점 생성
(`cmake/generate_accents.cmake`)은 그대로이므로 색 목록 교체는 JSON 파일만
바꾸면 된다.

### S2.5 영향 범위

`domain/appearance`(+override·합성), `domain/project`(문서 필드),
`json_workspace_document`(파싱·알 수 없는 필드 목록), `json_project_store`
(쓰기), `logic_controller`(`effective_appearance`·intent 분기·배지),
`view_snapshot`(+`theme_follows_app`·`accent_follows_app`),
`settings_dialog_element`(격자), `assets/accents.json`.

## S3. 창 배치의 범위

### S3.1 현황

`handle_window_placement`는 문서 유무와 무관하게 앱 설정과 문서 양쪽에 배치를
남긴다. 배치 intent는 UI thread가 `WM_CLOSE`에서 한 번만 보낸다. 그래서 문서를
연 채로 끄면 그 문서의 배치가 앱 설정에도 남고, 다음에 문서 없이 시작하면 그
크기로 열린다.

### S3.2 결정: 문서가 열려 있으면 앱 설정을 건드리지 않는다

| 상황 | 앱 설정 `window` | 문서 `window` |
|---|---|---|
| 문서 없음 + 배치 변경 | 갱신 | — |
| 문서 있음 + 배치 변경 | **건드리지 않음** | 갱신 |
| 문서를 여는 순간 | **여기서 한 번 갱신**(직전 배치) | 문서 값이 창에 적용된다 |
| 문서를 닫음 | 이후 배치 변경이 다시 앱 설정으로 간다 | — |

적용 우선순위(복원)는 그대로다: 여는 문서의 배치 > 앱 설정 > 기본값.

문서를 여는 순간의 배치를 남기려면 logic이 **현재 배치를 알고 있어야** 한다.
지금은 종료 직전에만 배치가 오므로, UI thread가 배치를 다음 시점에도 보낸다.

- `WM_EXITSIZEMOVE` — 이동·크기 조절이 끝난 시점.
- `WM_SIZE` 중 최대화 ↔ 복원 전환 — 끌기 중 연속으로 오는 `SIZE_RESTORED`는
  상태가 바뀐 경우에만 보낸다(메시지 폭주 방지).
- `WM_CLOSE` — 지금과 같다.

배치 intent는 저장을 곧바로 일으키지 않고 dirty 표시만 남기므로(현행) 자주
와도 비용이 없다. 문서를 여는 시점의 앱 설정 저장은 이미 그 경로가 내는 최근
문서 목록 저장에 함께 실린다.

### S3.3 영향 범위

`logic_controller`(현재 배치 보관, `handle_window_placement` 분기,
`install_document`에서 한 번 기록), `win32_application`(배치 게시 시점 추가),
`app_runtime`/`stabilization` test.

## S4. `덮어씀` 배지

### S4.1 현황

배지는 행 label 줄의 **오른쪽 끝**에 48×14로 붙는다. 항목과 멀고 얇아 무엇을
덮어썼는지 눈으로 잇기 어렵다.

### S4.2 결정: 항목 제목 왼쪽의 배지 열

배지를 **항목 제목 바로 옆(왼쪽)의 고정 열**에 둔다. 문서 모드에서는 모든 항목
제목이 이 열만큼 들여쓰여 제목이 세로로 정렬되고, 덮어쓴 항목에만 배지가 그려
진다. 배지는 높이 18, 좌우 여백이 있는 알약 모양이며 `accent_soft` 바탕 위에
`accent_emphasis_fg` 글자와 1px 테두리를 갖는다(지금의 14 높이·테두리 없음보다
두껍다). 덮어쓴 항목은 배경에 옅은 `accent_soft`를 깔아 블록 자체가 구분된다.

**제목 오른쪽이 아니라 왼쪽인 이유**: 배치(`arrange`)는 logic thread에서
글꼴 없이 계산된다(`build_ui_tree`가 tree를 만들고 UI thread는 그리기만 한다).
제목 문자열의 실제 폭을 배치 시점에 알 수 없으므로 "제목 오른쪽에 딱 붙는"
좌표를 만들 수 없다. 고정 열이면 폭을 몰라도 항상 항목 바로 옆이고, 여러 항목의
배지가 세로로 정렬되어 어떤 항목이 문서 값인지 한눈에 들어온다.

| 값 | 논리 픽셀 |
|---|---|
| 배지 열 너비 (간격 포함) | 56 |
| 배지 크기 | 48 × 18 |

### S4.3 영향 범위

`settings_dialog_element`(배지 element와 항목 들여쓰기), `settings_dialog_tests`.

## 후속 요구 (2026-08-22 D1~D4)

첫 구현을 쓴 뒤 받은 지시 4건이다. 같은 문서에 이어 기록한다.

| 항목 | 요구 |
|---|---|
| D1 | 문서를 닫을 때 앱 단위 설정의 창 크기·위치로 복구한다 |
| D2 | 배지를 **오른쪽**에 둔다. 덮어쓰지 않은 항목도 비활성 색 `전역 설정` 배지로 표시하고, `덮어씀`은 `문서 설정`으로 바꾼다 |
| D3 | 색 목록을 되도록 정사각형에 가깝게, 비슷한 색끼리 한 줄에 오도록 배치한다 |
| D4 | 테마가 `저장`을 누르지 않아도 적용되는 문제를 고친다 |

### D1. 문서를 닫으면 앱 배치로 돌아간다

S3에서 앱 단위 배치는 "문서를 열지 않은 동안의 배치"가 되었다. 문서를 닫으면
다시 그 상태이므로 창도 그 배치로 되돌린다. `handle_close_document`가
`window_placement_`에 앱 설정의 배치를 싣고 게시 번호를 올려 UI thread가 한 번
적용한다(문서를 열 때 문서 배치를 적용하는 것과 같은 경로다). 앱 설정에 배치가
없으면 창을 건드리지 않는다.

### D2. 배지: 오른쪽 열 · `문서 설정` / `전역 설정`

왼쪽 배지 열은 덮어쓰지 않은 항목의 왼쪽을 비워 보기 나빴다. 배지를 항목 제목
줄의 **오른쪽 끝**으로 옮기고, 행 컨트롤(찾아보기·지우기·토글·테마 세그먼트)을
배지 열만큼 왼쪽으로 민다. 배지 열은 문서 모드에서만 자리를 차지한다.

| 상태 | 글자 | 모양 | 클릭 |
|---|---|---|---|
| 문서가 정의함 | `문서 설정` | `accent_soft` 바탕 + `accent` 테두리 + 강조 글자 | 정의를 지우고 전역을 따른다 |
| 정의하지 않음 | `전역 설정` | 바탕 없음 + 흐린 테두리 + 흐린 글자 | 없음 (tooltip만) |

두 배지 모두 같은 element 종류(`settings_override_badge`)이며 owner가 항목을
가리킨다. 전역 배지는 액션이 없어 눌러도 아무 일도 일어나지 않는다.

### D3. 색 격자: 정사각형에 가깝게

한 줄에 넣는 개수를 `ceil(sqrt(색 개수))`로 정한다(내용 폭이 모자라면 줄인다).
25색이면 5 × 5다. 줄 묶음은 **목록 순서**가 정한다 — `assets/accents.json`이
색상환 순서라 한 줄이 한 계열이 된다(블루·퍼플 / 마젠타·핑크 / 레드·오렌지 /
앰버·그린 / 민트·스카이). 색을 더할 때도 색상환 순서를 지키면 배치가 따라온다.
동그라미는 22 → 24로 키운다.

### D4. 외양도 `저장`/`취소` 초안을 거친다

지금까지 외양 2항목은 클릭 즉시 반영·저장했다(T3.3의 결정). 사용자 지시로
**다른 항목과 같은 초안 규칙**으로 바꾼다.

- dialog 상태에 `theme`·`accent_id` 초안과 `theme_defined`·`accent_defined`를
  둔다. 여는 순간 유효 값에서 시작하고, 문서 모드에서는 문서가 정의한 항목만
  `defined`다.
- 클릭은 초안만 바꾼다. 화면 색은 `저장` 전까지 그대로다.
- `저장`이 문서 모드에서는 문서 `appearance` override를, 전역 모드에서는 앱
  설정의 `appearance`를 쓴다. `취소`는 초안을 버린다.
- `전역 설정`/`문서 설정` 배지도 초안을 가리킨다. 배지 클릭은 초안의 정의를
  거두고 앱 값을 다시 보인다(다른 항목과 같다).

`set_theme_preference_intent`·`set_accent_intent`는 dialog가 열려 있을 때만
뜻이 있다. 닫힌 뒤 도착한 클릭은 버린다.

## 후속 요구 (2026-08-22 E1~E3)

배지와 초안을 쓴 뒤 받은 지시 3건이다.

| 항목 | 요구 |
|---|---|
| E1 | `외양` 탭 이름을 `테마`로 바꾼다 |
| E2 | 테마에서 값을 고르면 즉시 보여 주되, `취소`하면 되돌린다 |
| E3 | 배지가 오른쪽 끝에 붙어 한 줄의 조작 요소를 모두 밀어낸다. 세부 설정 바로 옆이나 **바로 위**에 붙인다 |

### E1. 탭 이름

표시 문자열만 `테마`로 바꾼다. 열거자(`settings_tab::appearance`)와 element의
owner 값(`appearance`)은 저장·정체성에 쓰이고 있어 그대로 둔다.

### E2. 초안 미리 보기와 롤백

D4에서 외양을 초안으로 바꾸면서 미리 보기까지 사라졌다. 초안은 유지하되
**dialog가 열려 있는 동안에는 초안을 그대로 그린다.**

- `make_view_snapshot`이 `appearance`에 유효 값을 담은 뒤, dialog가 열려 있으면
  초안의 테마·키 컬러로 덮는다. UI thread의 해석(고대비 > 명시 > 시스템)은 그대로다.
- `저장`이 초안을 문서 override나 앱 설정에 남긴다. `취소`는 초안을 버리므로
  다음 snapshot부터 원래 색으로 돌아간다(별도 롤백 코드가 없다).
- 문서·앱 설정 파일은 `저장` 전까지 바뀌지 않는다.

### E3. 배지는 항목 제목 **바로 위**

오른쪽 끝 배지는 같은 줄의 찾아보기·지우기·토글·세그먼트를 모두 왼쪽으로 밀어
줄마다 조작 요소의 오른쪽 끝이 흔들렸다. 배지를 항목 제목 **바로 위 왼쪽**으로
옮기고 컨트롤은 제목 줄 오른쪽 끝을 그대로 쓴다.

- 요구의 첫 번째 안(제목 **바로 오른쪽**)은 배치가 글꼴 없는 logic thread에서
  계산되어(`build_ui_tree`) 제목 문자열의 실제 폭을 알 수 없어 성립하지 않는다.
  두 번째 안인 "바로 위"를 골랐다.
- 덮어쓸 수 있는 항목만 배지 줄(20px)을 갖는다. 파일 연결처럼 문서 설정이 아닌
  항목은 줄을 만들지 않는다.
- 전역 모드에는 배지 줄이 없어 항목 높이가 그대로다.
