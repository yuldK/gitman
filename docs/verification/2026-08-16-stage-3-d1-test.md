# 단계 3 `S3-D1-TEST` 검증 기록 - 2026-08-16

## 1. 결과

`S3-D1-CODE`에서 만든 계약 계층의 test만 작성했다. Catch2 test 24개를 추가하고 `gitman_tests`에 `gitman_process` 링크를 연결했다. 자식 프로세스를 실행하는 test와 도우미 실행 파일은 `S3-D2-TEST` 범위이므로 포함하지 않았다.

이번 구간에서 발견한 production 결함은 없다. 따라서 `S3-D1-FIX`는 사용자 확인 후 생략 대상이다.

사용자 승인에 따라 기존 clang-format 기준선 3개 파일도 formatter 결과로 정렬했다. 상세는 5장에 있다.

## 5. format 기준선 처리

`S3-D1-CODE` 5장에서 보고한 aggregate `gitman_format_check` 실패를 사용자 승인에 따라 **clang-format 결과 수용** 방향으로 해소했다.

- `src/platform/win32/utf8.cpp`: 조건 연산자 두 곳이 한 줄로 합쳐졌다.
- `src/platform/win32/win32_application.cpp`: `SetWindowPos` 호출과 hit test 조건식이 formatter 배치로 바뀌었다.
- `src/presentation/ui_theme.h`: `make_ui_color`의 bit 조합 표현식이 한 줄이 되었다.

세 파일 모두 줄바꿈 배치만 달라졌고 토큰 순서와 의미는 그대로다. `docs/code_style.md` 2장에는 `ColumnLimit` 200 안에 들어가는 표현식에서 formatter 결과가 기준이라는 문장을 추가해 문서와 자동 검사가 어긋나지 않게 했다.

정렬 후 VS2022 Debug/Release, VS2026 Debug, `/analyze`, 전체 CTest와 aggregate 검사를 다시 실행해 모두 통과했다.

## 6. 발견한 결함

없다. 24개 test 모두 첫 실행에서 기대한 계약대로 통과했다.

test 작성 중 다음 두 항목은 계약 확인 사항으로 정리했으며 production 변경이 필요하지 않았다.

- 이동한 `process_cancellation_source`는 `shared_ptr` 이동 결과로 빈 상태가 되어 취소를 발행하지 않는다. 소유권 이전 후 원본을 계속 쓰지 않는 사용 계약과 일치한다.
- 취소 시점에 살아 있던 구독만 통지되고, 이후 등록은 즉시 실행된다. 따라서 경합 상황에서 통지 수는 등록 수 이하이며 정확한 수를 단정할 수 없다. test는 상한과 취소 상태만 확인한다.
