# 검증 기록 - 단계 7 `S7-D1` 로그 model과 변경 작업 배관

## 1. 개요

- 날짜: 2026-08-18
- 대상: `S7-D1` (docs/stage-7-plan.md 5장)
- 진행 방식: 사용자 위임에 따른 자동 진행 (2026-08-18 지시)

## 2. 구현 내용

- `domain/operation_log.h/.cpp`: 카드 로그 record(`operation_log_entry`,
  `operation_log_record`)와 카드별 ring buffer(`operation_log_buffer`, 상한
  1,000 record)를 추가했다. sequence는 append 시점에 카드별 단조 증가로 부여하고,
  상한 초과 제거 수와 총 발행 수를 분리해 보고한다 (plan 3.9).
- `application/app_messages.h`: intent 4종(`request_update_intent`,
  `request_switch_intent`, `cancel_operation_intent`, `clear_log_intent`),
  `operation_kind` 3종(`update`, `switch_to`, `query_switch_candidates`),
  event 3종(`operation_log_event`, `change_completed_event`,
  `switch_candidates_event`)을 추가했다. `operation_request`가 `update_options`와
  전환 대상을 나른다.
- `infrastructure/vcs_operation_executor`: 변경 작업 실행(`execute_change`)과
  후보 조회(`execute_switch_candidates`)를 추가했다. 변경 작업의 모든 프로세스
  출력은 provider의 log sink 자리에 꽂힌 `operation_log_forwarder`가 16 record
  배치로 `operation_log_event`로 옮기고, 명령 종료 시 flush가 완료 event보다
  먼저 나간다. 최상위 예외 경로도 새 종류에 맞는 final event를 보낸다.
- `application/logic_controller`: 카드 상태에 로그 buffer와 변경 작업
  상태(작업 id, 종류, 작업별 취소 source)를 추가했다.
  - 변경 작업은 카드 단위 취소가 가능하도록 전역 token 대신 작업별
    `process_cancellation_source`의 token을 싣는다. 종료·문서 교체 시 실행 중인
    변경 작업을 모두 취소한다.
  - busy 카드의 중복 변경 요청은 시작하지 않고 사유를 경고 로그로 남긴다.
  - `change_completed_event`는 작업 id가 일치할 때만 반영한다. 실행 직후 재조회
    snapshot은 availability가 unknown이 아닐 때만 카드에 적용해, 도구 부재처럼
    조회 없이 차단된 결과가 카드 상태를 지우지 않는다.
  - 완료 후 성공 여부와 관계없이 자동 refresh(remote-first)를 이어 실행한다
    (plan 5.2의 8).
  - 수명 주기(시작·완료·실패·차단·거부·취소 요청)와 오류 진단을 로그로 남긴다.
  - `card_log()` 읽기 전용 접근자를 두어 view 구성(`S7-D2`)과 test가 buffer를
    관찰한다.

## 3. 테스트

새 test 19개 (전체 CTest 544 → **563**).

- `operation_log_tests.cpp` (3): sequence 부여, 상한 초과 시 오래된 record 제거와
  집계, clear 후 sequence 연속.
- `logic_change_operation_tests.cpp` (12): update 요청의 작업별 token, busy 중복
  거부와 로그, 완료 후 snapshot 반영과 자동 refresh 연쇄(generation 증가), 차단
  결과가 카드 상태를 지우지 않음, 늦은 완료·로그 폐기, **병렬 두 카드의 로그
  격리(REQ-008)**, 카드 단위 취소가 그 작업 token만 신호, switch 요청의 후보
  전달, 로그 지우기, 종료 시 변경 작업 취소, 문서 교체 시 취소, 제출 실패 복원.
- `vcs_operation_executor_tests.cpp` (+4): 도구 없는 update의 차단 final event와
  프로세스 0개, 대상 없는 switch의 거부와 프로세스 0개, 도구 없는 후보 조회의
  event 보장, **변경 작업 출력의 로그 event 스트리밍(stdout/stderr)과 완료 event
  순서**.
