# 단계 2 `S2-D3-TEST` 검증 기록 - 2026-08-15

## 1. 결과

`.version-list` project path production code를 대상으로 runtime filesystem fixture와 Catch2 test 7개를 추가했다. document 기준 상대 path, Windows path 정규화, filesystem 상태, workspace 부분 성공, 중복 제거와 원래 JSON project index 보존을 검증했다.

VS2022와 VS2026 Debug build 및 전체 CTest 41/41이 모두 통과했다. 이번 체크포인트에서 production source는 변경하지 않았고, `S2-D3-FIX` 대상으로 기록할 production 결함도 발견하지 않았다. 사용자가 test 검수를 완료 처리했으며 `S2-D3-FIX`는 수정 없이 생략했다.

## 2. 추가한 test 범위

| test | 검증 내용 |
| --- | --- |
| `Project paths resolve relative to workspace documents` | process working directory가 아니라 `.version-list` 상위 디렉터리를 기준으로 상대 path를 해석하고 `.`, `..`, slash, trailing separator, 한글, emoji와 공백을 정규화한다. |
| `Project paths normalize drive extended and UNC forms` | mixed-separator drive path, `\\?\` drive, UNC와 `\\?\UNC\`를 같은 lexical 형식으로 정규화한다. |
| `Project path states distinguish directories files missing and invalid inputs` | 실제 directory, 일반 file, missing path, wildcard, drive-relative, root-relative, device/volume namespace, 잘못된 UTF-8과 기준 문서가 없는 상대 path를 구분한다. |
| `Project paths preserve Unicode spaces and long lexical values` | 260 byte를 넘는 한글, emoji와 공백 포함 path를 손실 없이 정규화하고 extended-length filesystem 조회를 수행한다. |
| `Workspace path resolution excludes invalid and duplicate projects` | schema 오류 뒤의 유효 project, 대소문자 무시 duplicate, missing, invalid와 file을 함께 처리하고 diagnostic의 JSON pointer 및 원래 project index를 보존한다. |
| `Workspace path resolution ignores failed schema documents` | document-level parse 실패에는 filesystem 후처리를 적용하지 않는다. |
| `Normalized project path equality is ordinal and case insensitive` | Windows ordinal case-insensitive path 비교와 서로 다른 path의 비동등성을 검증한다. |

## 3. runtime fixture

- test마다 `std::filesystem::temp_directory_path()` 아래에 충돌하지 않는 전용 디렉터리를 만든다.
- 실제 directory와 일반 file을 생성하고 fixture 소멸 시 전용 디렉터리를 재귀 정리한다.
- 사용자별 절대 path나 repository 내부의 고정 filesystem artifact에 의존하지 않는다.
- loopback UNC의 존재하지 않는 share는 로컬 SMB 구성에 따라 `missing` 또는 `inaccessible`이 될 수 있어 두 unavailable 결과를 허용한다. drive 및 UNC의 lexical 결과는 환경과 무관하게 정확히 검증한다.

`src/` production source와 기존 test source 및 fixture는 변경하지 않았다.

## 5. 검증 결과

| 검증 | 결과 |
| --- | --- |
| VS2022 Debug build | 신규 path test를 포함해 통과 |

| `ctest --preset vs2022-debug --output-on-failure` | 전체 41/41 통과 |

build child process는 기존과 같이 중복 `PATH`/`Path`를 하나의 `Path`로 정규화했다. VS2026 build는 기존 sandbox FileTracker 제한 때문에 host 권한에서 실행했다.

## 6. 작성 중 검토 결과

첫 build에서 test helper 이름이 `std::filesystem::create_directories`와 ADL 충돌한 문제와 Catch2 expression decomposition에서 논리합 식에 괄호가 필요했던 문제를 test source 안에서 수정했다. 두 항목 모두 test 작성 결함이며 production 동작에는 영향이 없다.

현재 알려진 production 결함과 `S2-D3-FIX` 후보는 없다.

## 7. 검수 완료

사용자가 2026-08-15에 `S2-D3-TEST`를 검수 완료 처리했다. 발견 production 결함이 없어 `S2-D3-FIX`를 생략 완료로 기록하고 `S2-D4-CODE`의 save/recovery production code 구현으로 진행했다.
