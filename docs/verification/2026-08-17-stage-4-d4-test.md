### 2.1 fixture의 출처

실제 `svn.exe`가 없어 출력을 캡처할 수 없다. 계획 8.4대로 **Apache Subversion 공식 문서의 출력 계약을 근거로 작성하고 출처를 파일 안에 남겼다.** 주석은 `#`로 시작하는 줄이며 test 도우미가 버린다. SVN은 상태 줄을 `#`로 시작하지 않으므로 실제 출력과 충돌하지 않는다.

fixture 파일에는 "실제 `svn.exe` 출력과 대조하지 않았다"는 사실도 함께 적었다.

### 2.2 파서 test

- `--show-item` 값 추출: 정상, 앞뒤 공백, 빈 줄 건너뛰기, 여러 줄에서 첫 값, 빈 출력
- `status` 상태 문자 12종(`M`, ` M`, `MM`, `A +`, `D`, `R`, `!`, `~`, `C`, `?`, `I`, `X`)과 요약 매핑
- switched(5번 칸)와 tree conflict(7번 칸), `> moved from` 같은 부가 설명 줄을 항목으로 세지 않는 것
- 상태 칸 뒤 패딩이 하나 더 있어도 경로가 잘리지 않는 것. 계획의 "고정 9칸" 대신 공백을 건너뛰는 구현의 근거를 test로 고정했다
- 공백·한글·emoji가 든 경로와 경로가 없는 줄(해석 실패)
- `svnversion`: 단일 리비전, 범위, `M`/`S`/`P` 조합, 앞뒤 공백, `Unversioned directory`, `exported`, 빈 줄, 끊긴 범위, 모르는 접미사. 해석 실패 시 부분값도 남기지 않는 것

무시(`I`)와 외부 항목(`X`)이 어느 수에도 들어가지 않는 것과, 해석 실패가 있으면 작업 트리 상태가 `unknown`이 되는 것도 단정한다.

### 2.3 provider test

`fake_process_runner`가 기록한 요청으로 단정한다.

| 조건 | 단정 |
| --- | --- |
| 도구 부재 | `tool_unavailable`, 오류 아님, **요청 0개**(로컬과 원격 모두) |
| 상대 경로, 사라진 경로 | `path_unavailable`, **요청 0개** |
| 작업 복사본 아님(`E155007`) | `not_a_repository`, 첫 조회에서 멈춤(요청 1개) |
| 정상 | 요청 7개, 순서가 `wc-root` → `relative-url` → `revision` → `repos-root-url` → `repos-uuid` → `status` → `svnversion` |
| 정상 | `svnversion`이 다른 실행 파일이고 **인자가 없음**, 로컬 조회에 URL 인자가 없음 |
| mixed·switched | `svnversion`의 `4123:4168MS`로 두 값 모두 참 |
| `svnversion` 부재 | 요청 6개, `has_mixed_revision`은 **값 없음**, switched는 `status`로 보조 판정 |
| `svnversion` 해석 실패 | warning 진단, 나머지 결과 유지, 오류 아님 |
| `status` 실패 | `unknown`, 작업 트리도 `unknown` |
| timeout | `unknown`과 `process_timed_out` 진단 |
| 원격 behind | `behind` 12, `ahead_count`는 0, `comparison=remote`, 확인 시각 |
| 원격 up_to_date | 차이 0, 진단 없음 |
| 원격 실패 3종 | `E170013`→`offline`, `E215004`→`authentication_required`, `E155010`→`error`. 실패해도 로컬 상태 보존 |
| 리비전 해석 실패 | `error`와 `vcs_output_unparsable` |
| 로컬 미준비 | 요청 0개 |
| 미구현 3개 동작 | `executed == false`, 요청 0개 |

실패 분류 test는 모두 **한국어 메시지**에 SVN 오류 코드가 붙은 형태다. 번역된 메시지에도 코드가 그대로 남는다는 전제를 언어에 의존하지 않고 단정한다.

### 2.4 통합 test와 skip

| test | 이 호스트에서 |
| --- | --- |
| SVN이 없는 호스트에서 앱이 계속 동작한다 | **실행됨.** `not_found`, 실행 파일 경로 비어 있음, 진단이 모두 warning, provider가 `tool_unavailable`만 보고하고 명령을 만들지 않음 |
| 실제 `svn.exe`로 비작업복사본 판정 | **skip.** "호스트에 사용할 수 있는 SVN이 없어 통합 test를 건너뜁니다" |

두 test는 서로 배타적이다. SVN이 설치된 호스트에서는 첫 test가 skip되고 둘째 test가 실행된다.

실제 작업 복사본을 만들려면 `svnadmin`이 필요하다. 단계 4는 실행 파일 연결과 판정까지만 확인하고, 실제 작업 복사본 통합 검증은 단계 8의 SVN 환경 작업으로 남긴다. 사용자 방침(개발 시점에 SVN을 쓰지 않고 나중에 최소 노력으로 붙인다)에 맞춘 범위다.

## 6. 여전히 미검증인 범위

`S4-D4-CODE` 기록 7장의 네 항목이 그대로 남는다. test는 fixture와 fake runner로 규칙을 고정할 뿐 실제 도구 동작을 확인하지 못한다.

- 실제 `svn.exe`와 `svnversion.exe` 실행 경로
- `status`의 실제 칸 패딩. 패딩이 달라도 동작하도록 만들었고 그 사실을 test로 고정했지만 실측은 아니다
- 원격 조회의 실제 인증·연결 실패 메시지에 붙는 오류 코드
- `info --show-item`이 값 외의 줄을 내는 배포판이 있는지 여부

실제 SVN 환경에 붙일 때 이 네 가지만 확인하면 되고, 어긋나면 파서 한 곳을 고친 뒤 이 구간의 fixture를 실제 출력으로 교체하면 된다.
