# 단계 2 `S2-D2-TEST` 검증 기록 - 2026-08-14

## 1. 결과

schema version 1 parser의 fixture와 계약 test 작성을 완료했다. 신규 test 8개를 포함한 CTest 34개가 VS2022와 VS2026 Debug에서 모두 통과했으며 parser production 결함은 발견되지 않았다. 사용자가 진행을 지시해 test 검수를 승인했다.

이번 체크포인트에서는 `src/` production source를 변경하지 않았다. test source, fixture, test target 연결과 `.version-list` test asset의 파일 형식 검사 범위만 변경했다.

## 2. 추가한 test

| test | 검증 범위 |
| --- | --- |
| `Schema parser loads complete and defaulted projects` | 전체 field, 한글 및 emoji UTF-8, optional 값과 생략 기본값, display name 파생 |
| `Schema parser accepts minimal and empty documents` | schema version 1 최소 문서와 빈 projects |
| `Schema parser rejects malformed JSON and invalid roots` | 손상 fixture, array root와 잘못된 UTF-8의 문서 수준 거부 및 원문 보존 |
| `Schema parser rejects invalid document contracts` | 누락 및 잘못된 schema version, 누락 및 잘못된 projects type과 diagnostic 위치 |
| `Schema parser rejects unsupported versions without changing source` | version 0, 음수와 미래 version 거부 및 source shadow 보존 |
| `Schema parser returns valid projects from partially invalid input` | 유효 항목 유지, 필수 field 누락, 중복 ID, 잘못된 VCS hint와 non-object 항목 제외 |
| `Schema parser validates every project field` | ID, path와 모든 optional field의 type 및 값 오류 12종 |
| `Schema parser warns about unknown fields and preserves source bytes` | top-level/project warning, project 위치, JSON pointer escape와 정확한 원문 byte 보존 |

## 3. fixture

| 파일 | 목적 |
| --- | --- |
| `valid-complete.version-list` | 전체 field와 기본값을 함께 검증하는 정상 문서 |
| `malformed.version-list` | 닫히지 않은 projects 배열 |
| `partial-invalid.version-list` | 유효 및 잘못된 project가 섞인 부분 성공 문서 |
| `legacy-version.version-list` | 지원하지 않는 version 0 |
| `future-version.version-list` | 지원하지 않는 version 2 |
| `unknown-fields.version-list` | unknown field와 JSON pointer escape 및 원문 shadow |

fixture는 실제 사용자 문서 확장자인 `.version-list`, UTF-8 무 BOM과 CRLF를 사용한다. source style 및 line-ending 정규화 도구도 이 확장자를 검사하도록 test asset 범위를 확장했다.

## 5. 검증 결과

| 검증 | 결과 |
| --- | --- |
| 신규 schema parser test | 8/8 통과 |
| project field 오류 matrix | 12/12 통과 |
| VS2022 Debug build | 통과 |
| `ctest --preset vs2022-debug --output-on-failure` | 34/34 통과 |
| VS2026 Debug build | host 환경에서 통과 |
| `ctest --preset vs2026-debug --output-on-failure` | 34/34 통과 |
| clang-format dry run | 신규 test source 통과 |
| source style | 94개 파일 통과 |
| `.version-list` UTF-8 무 BOM 및 CRLF | fixture 6개 통과 |
| `git diff --check` 및 `git diff --cached --check` | 통과 |
| production source 변경 | 없음 |

직접 실행한 첫 VS2022 build는 Codex process 환경의 중복 `PATH`/`Path` 때문에 compiler 시작 전에 실패했다. build child의 경로 키만 하나로 정규화한 뒤 통과했다. VS2026 build는 기존 sandbox FileTracker 제한 때문에 host 권한에서 실행했다.

## 6. test 작성 중 발견 사항

첫 전체 test 실행에서는 `partial-invalid.version-list`가 잘못된 malformed fixture에 이어 붙어 별도 파일로 생성되지 않은 test asset 구성 오류가 1건 발생했다. fixture를 분리한 뒤 해당 test와 전체 test가 통과했다. parser production 결함은 아니며 production source는 변경하지 않았다.

현재 `S2-D2-FIX` 대상으로 기록할 production 결함은 없다.

## 7. 다음 검수 게이트

사용자 승인에 따라 `S2-D2-FIX`를 수정 없음으로 생략하고 `S2-D3-CODE`의 경로 정규화, path 상태와 중복 경로 판정 production code만 진행한다.
