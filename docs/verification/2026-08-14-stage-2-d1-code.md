# 단계 2 `S2-D1-CODE` 검증 기록 - 2026-08-14

## 1. 결과

도메인 값 type과 구조화 diagnostic production code 구현을 완료했고 사용자가 `S2-D1-TEST` 시작을 지시하여 코드 검수를 승인했다. 이 체크포인트에서는 새 test source와 fixture를 작성하지 않았고 production bug 수정 구간도 시작하지 않았다.

## 2. 사용자 계획 수정 반영

- 프로젝트 목록은 고정 `projects.json`이 아니라 solution 및 `.code-workspace`와 같은 user-owned 작업공간 문서다.
- 확장자는 사용자 지시의 철자를 그대로 적용한 `.version-list`다.
- 한 프로세스 및 창은 한 문서를 활성화한다.
- shell positional path 인식은 단계 2의 `S2-D5`, 실제 Windows file association 등록 및 제거는 단계 8에서 구현한다.

## 3. production code 범위

새 `gitman_domain` static library를 만들고 다음 모델을 UI 및 infrastructure와 분리했다.

- `project_id`, `project_path`, `project_definition`, `workspace_document`
- schema version 1과 `.version-list` 확장자 상수
- `vcs_hint`와 configured path 상태
- Git/SVN 공통 `repository_snapshot`, 원격 동기화 및 작업 트리 상태
- `operation_id`, 작업 종류와 실행 상태
- 안정적인 diagnostic severity, code, JSON pointer와 project source 위치

도메인 public header는 Win32, Skia와 nlohmann/json을 포함하지 않는다.

## 4. 변경 파일

- `src/domain/diagnostic.h`, `src/domain/diagnostic.cpp`

`tests/` 아래 파일은 변경하지 않았다.

## 5. 검증 결과

| 검증 | 결과 |
| --- | --- |
| VS2022 Debug build | 통과 |
| `ctest --preset vs2022-debug --output-on-failure` | 기존 20/20 통과 |
| VS2026 Debug build | host 환경에서 통과 |
| `ctest --preset vs2026-debug --output-on-failure` | 기존 20/20 통과 |
| source style | 80개 파일 통과 |
| `git diff --check` | 통과 |
| domain dependency scan | Win32, Skia, nlohmann/json 참조 없음 |
| 새 test source 및 fixture | 없음 |

첫 VS2022 build는 Codex 환경에 대소문자만 다른 `PATH`와 `Path`가 함께 들어 있어 MSBuild가 `CL.exe` process 환경을 만들지 못했다. build child process에서만 두 값을 하나의 `Path`로 정규화한 뒤 같은 build가 통과했다.

VS2026의 최초 sandbox build는 기존 단계 1 기록과 동일하게 MSBuild FileTracker가 `E_ACCESSDENIED`로 실패했다. 동일 command를 host 권한으로 다시 실행해 성공했으므로 project code 오류가 아니다.

## 6. 검수 항목

- `.version-list` 철자와 workspace document 상수가 사용자 의도와 일치하는지
- domain model의 project, repository snapshot과 operation 범위가 후속 provider에 적절한지
- diagnostic code가 schema, path, 저장과 복구 오류를 충분히 구분하는지
- domain target의 infrastructure 독립성이 적절한지

사용자 승인에 따라 다음 체크포인트는 새 production 기능을 추가하지 않고 domain model test만 작성하는 `S2-D1-TEST`다.
