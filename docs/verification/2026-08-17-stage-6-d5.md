### 2.1 핵심 결정

- **UI thread는 snapshot만 그린다.** `WM_APP` wake → `InvalidateRect` → paint에서 `acquire_view()`로 마지막 view를 얻고 같은 순수 함수 `compute_layout`으로 배치를 계산한다. 연속 게시는 `latest_slot`의 batch signal과 Win32 pump에서 자연히 병합된다.
- **smoke test 경로는 스레드를 만들지 않는다.** 기존 4종 renderer smoke test가 그대로 유효하다.
- **종료 순서** (ADR-005 7.3): `WM_CLOSE` → close intent(취소 전파) → scheduler(worker join) → logic inbox close·join → input close·join → slot close → 창 파괴. `WM_DESTROY`만 오는 경로도 같은 정리를 거친다.
- 파일 dialog는 UI thread에서만 연다. input thread의 요청은 `WM_APP` 메시지로 marshal된다.
- `app_runtime`은 `HWND`가 null이면 wake 게시를 생략한다. 창 없는 조립 test가 이 경로로 **실제 스레드 4종 + 실제 store + 실제 provider** 전체를 돌린다.

## 3. test 범위 (2개)

- **조립 전체의 실제 왕복**: 임시 문서(.verison-list)와 실제 디렉터리로 runtime을 만들고, 문서 열기 → worker의 실제 store load → 카드 생성 → 실제 provider의 초기 로컬 조회(비저장소 → `failed`/`not_a_repository`)까지 view snapshot으로 관찰한다. 이 test는 이 호스트의 실제 `git.exe` 발견까지 포함한 end-to-end다.
- **빈 조립의 초기 snapshot과 무작업 종료**: 초기 게시가 `no_document`이고 shutdown이 멱등으로 hang 없이 끝난다.

창을 실제로 띄우는 수동 검증(카드 표시, refresh 클릭, DPI, caption)은 `S6-V1`의 수동 checklist 항목이다.
