## 4. 배포 절차 검증 (stage-8-plan 5.7)

- **배포 문서**: `docs/deployment.md`를 작성했다 — 지원 환경·prerequisite,
  단일 exe 설치, association 등록·제거, 사용자 데이터 위치(`.version-list`·
  `.bak`·HKCU 연결), 업그레이드(exe 교체, 스키마 1 유지), 백업·복구, 제거,
  제3자 고지, 알려진 제한.
- **file association 실측** (설치본, 실제 HKCU): `--register-file-association`
  종료 코드 0 → `.version-list` 기본값 `Gitman.VersionList`, open command
  `"E:\...\bin\gitman.exe" "%1"` 확인 → `--unregister-file-association` 종료
  코드 0 → 확장자·ProgID 키 잔여물 없음.
- **라이선스 고지**: Skia·nlohmann/json·Codicons 고지문이 실행 파일 resource로
  embed되고, 의존성 목록과의 일치를 `dependency_versions_tests`·
  `embedded_assets_tests`가 검사한다 (전체 suite에 포함되어 통과).
- **구버전 문서 호환**: 스키마 버전 1 유지. 정상·손상·부분 오류·마이그레이션
  fixture 회귀 test가 전체 suite에서 통과한다 (단계 2 계약).

## 7. 검수 항목으로 남긴 수동 검증 (사용자)

1. 장시간 실행(2시간+) 중 메모리·핸들 단조 증가 없음.
2. 네트워크 단절 시 `offline` 표시·무한 대기 없음·재연결 복귀.
3. 문서 동시 수정 후 저장 시 충돌 notice 표시.
4. association 등록 상태에서 `.version-list` double-click으로 창 열림.
5. 대량 로그 출력 중 로그 pane 스크롤·복사·지우기 응답성.

## 8. 후속 항목 목록 (단계 계획 밖, 필요 시 별도 지시로 진행)

1. 정렬 전환 UI (name/status/custom 전환 버튼 — 현재 intent만 존재).
2. 스크롤 막대 Page Up/Down 키보드 이동.
3. 파일 로그 (보존 기간·저장 위치 정책, plan 3.9).
4. switch·탐색 dialog 후보 행의 가시 범위 생성 (후보 수백 개 대비).
5. `.git` 파일 후보의 worktree/submodule 구분 표시 (파일 내용 읽기 계약 필요).
6. `vcs_file_probe`의 존재/접근 실패 구분 계약 확장 (탐색 `inaccessible` 관찰).
7. submodule 내부 dirty의 update 사전 검사 (`git submodule status`는 미보고).
8. 제3자 고지문 열람 UI (현재 resource embed까지, 앱 내 표시 화면 없음).
9. 전체 앱 진단 로그 화면·파일 분리 (plan 3.9).
10. SVN 실측 4항목 (실서비스 적용 시 — `docs/handoff.md` 8.6).
11. `repository_query_result`/`repository_change_result`의 오류 API 비대칭 정리.

## 9. 알려진 제한

- SVN 경로는 fixture·fake runner 검증까지다 (2026-08-19 사용자 결정: 실서비스
  적용 시 검증. 구현은 Git과 같은 구조로 완료되어 있다).
- 네트워크 드라이브·실제 느린 경로의 탐색·조회는 검증하지 못했다.

  (credential helper 응답, `S8-D5` 3장).
