# 앱 셸 배치 — 앱 설정·시작 페이지·실행 인자·알림·문서 닫기·로그 파일

날짜: 2026-08-22 · 설계: `docs/app-shell-design.md` (A1~A5)

## 1. 변경 요약

문서 밖의 상태(앱 단위 설정)와 문서 폴더에 남는 산출물(로그 파일)이 처음 생겼다.

| 항목 | 내용 |
|---|---|
| A1 | 실행 파일 옆 `gitman.app-settings.json`에 최근 문서 10개. 문서가 없을 때 시작 페이지 표시 |
| A2 | 명령줄 인자·drag & drop·파일 선택기 경로를 절대 경로로 정규화 |
| A3 | 파일 연결 등록·해제 결과를 앱 스타일 알림 다이얼로그로 표시 |
| A4 | 카드 로그를 `.<문서>.version-list.log` 폴더에 저장소별 파일로 적재 |
| A5 | 문서 닫기 버튼 추가, 문서가 열려 있으면 새 문서 만들기 숨김, 새로 고침 왼쪽 끝·닫기 오른쪽 끝 배치 |
| 부수 | 문서·앱 설정 저장의 `.bak` backup 생성과 복구 경로 제거 (사용자 지시) |

## 2. 구현 경계

- **앱 설정**: `domain/app_settings`가 경로 열쇠 정규화·표시 이름·목록 병합의
  순수 규칙을 갖는다. 파일 접근은 `load_app_settings`/`save_app_settings` 작업
  2종으로 문서 lane에서 직렬화하며 logic thread는 파일을 만지지 않는다. 읽기
  완료 전 문서를 열면 저장을 보류했다가 파일 내용 위에 합쳐 한 번만 쓴다.
  실행 파일 폴더에 쓸 수 없으면 저장만 실패하고 사유는 세션당 한 번 알린다.
- **시작 페이지**: `no_document`일 때 카드 목록 자리를 차지한다. 스크롤 상태를
  새로 두지 않고, 남은 높이에 들어가는 행만 그린 뒤 "외 N개"로 알린다. 시작
  페이지에서는 하단 로그 pane을 두지 않는다.
- **경로 정규화**: `win32::absolute_workspace_document_path`가 기존 경로 준비·
  `GetFullPathNameW` 조각을 재사용한다. 펼 수 없는 형식은 원본을 그대로 보내고
  존재 여부는 확인하지 않는다(열기 실패 진단이 사유를 보고).
- **알림 다이얼로그**: UI thread가 registry 작업을 수행한 뒤 `show_notice_intent`
  로 logic에 결과를 넘긴다. 다른 dialog 위·컨텍스트 메뉴 아래에 그려지고 Esc는
  알림을 가장 먼저 닫는다. 창이 없는 명령줄 모드는 MessageBox를 유지한다.
- **문서 닫기**: 변경 작업 취소 → 미반영 창 배치 1회 저장 → 문서·카드·선택·
  필터·로그·dialog 상태 정리 순서다. 최근 목록은 유지한다. 문서 변경은 항상 즉시
  저장되므로 확인 창을 두지 않았다.
- **로그 파일**: 루트는 문서 폴더의 `.<문서 이름>.log`다. 저장소 폴더 이름은
  문서 단위 순수 함수가 정한다(마지막 폴더명 → 겹치는 것만 상위 세그먼트 누적
  → 드라이브·share). 적재 경로는 logic → 비차단 큐 → 전용 writer thread →
  파일이며, 큐 상한 초과는 오래된 항목부터 버리고 유실 수를 파일에 남긴다.
  폴더 생성·쓰기 실패는 그 문서의 파일 로그만 끄고 사유를 카드 로그에 한 번
  남긴다. 문서 설정 `write_log_files`(기본 켬)로 끌 수 있다.
- **backup 제거**: `atomic_commit`이 `ReplaceFileW` 대신
  `MoveFileExW(MOVEFILE_REPLACE_EXISTING | WRITE_THROUGH)`를 쓴다. 임시 파일
  속성(temporary·not indexed)을 교체 전에 지운다. `load_backup`,
  `workspace_document_source`, `backup_invalid`/`recovery_available` 진단,
  commit 실패의 `restore`를 함께 삭제했다.

## 3. 자동 검증

- **Debug**: 앱·테스트 빌드 성공, 전체 CTest **714 통과 / 0 실패**
  (실제 Git 원격·SVN 실행 3건 skip). ASan 17 case와 renderer smoke 4건 포함.
- **Release**: 테스트 빌드 성공, 전체 CTest **714 통과 / 0 실패**(같은 3건 skip).
- **정적 분석**: `vs2022-analysis` preset 빌드 성공, 새 경고 없음.
- **앱 Release 빌드**: `gitman.exe` 빌드 성공, `--smoke-test`(auto)와
  `--smoke-test --renderer=cpu` 모두 종료 코드 0.
- **스타일**: `check_source_style.ps1` 418 files 통과. clang-format은 이번 배치가
  건드린 파일에서 위반 없음(기존 파일의 선재 위반은 그대로 남아 있다).
- 이번 배치의 신규 test는 45 case다: 앱 설정 도메인·JSON·store·logic 병합(12),
  시작 페이지 view/tree/hit(5), 경로 정규화(1), 알림·문서 닫기·도구 막대 배치(6),
  로그 파일 이름 규칙·writer·실패·logic 배선·설정·실제 Win32 파일 접근(13),
  그 밖에 기존 toolbar·backup 기대치를 바꾼 수정분.

## 4. 실환경 확인 결과

- 사용자 실행에서 로그가 정상 적재됨을 확인했다. 폴더가 저장소 폴더들 사이에
  섞여 찾기 어렵다는 피드백으로 로그 루트 이름 앞에 `.`을 붙였다(2026-08-22).
  이전 이름으로 만들어진 폴더는 그대로 남으며 자동으로 옮기지 않는다.

## 5. 남은 실환경 확인

1. 실행 파일이 보호된 위치(Program Files)에 있을 때 앱 설정 저장 실패 문구가
   한 번만 뜨고 최근 목록이 세션 동안 정상 동작하는지
2. 네트워크 드라이브·UNC 작업 복사본에서 로그 폴더 생성과 append 동작
3. 같은 문서를 여러 Gitman 인스턴스로 열었을 때 앱 설정의 마지막 저장 우선
   동작(최근 목록 일부 유실)이 실제로 문제되는지
4. 매우 긴 경로(260자 근처) 저장소에서 폴더 이름 자르기와 파일 생성
5. 파일 연결 등록·해제 알림이 실제 registry 실패(권한 등)에서 오류 문구로
   보이는지
