# 단계 5 `S5-D1` 검증 기록 - 2026-08-17

## 1. 결과

단계 5의 첫 구간으로 탐색 도메인 모델, 표식 판정 순수 함수, 깊이 1 열거 계약과 Win32 구현, 새 `gitman_discovery` target을 구현했다. 2026-08-17 사용자 지시에 따라 이번 단계부터 production code와 test code를 같은 구간에서 작성했으며, 판정 matrix·정렬·열거 계약 test 19개와 fake enumerator 도우미를 함께 추가했다.

VS2022 Debug/Release와 VS2026 Debug build 및 전체 CTest가 각각 **412/412** 통과했다(기존 393 + 신규 19). VS2022 `/analyze`가 경고 없이 통과했고 aggregate `gitman_format_check`(238개 파일), `gitman_source_style`, `git diff --check`도 통과했다. VS2022 Debug 전체 suite를 `--repeat until-fail:3`으로 반복해 flakiness가 없음을 확인했다.

발견 production 결함은 없다. 개발 중 formatter 위반 1건(`find_handle` 생성자 초기화 목록의 중괄호 여백)을 clang-format 결과 수용으로 같은 구간에서 해소했다.

### 2.2 판정을 순수 함수로 둔 방식

`classify_discovery_markers`는 filesystem을 보지 않는다. 입력은 자식 하나에서 확인한 표식 묶음(`repository_marker_set`)이고 출력은 종류·`via_git_file`·제외 사유다. 표식을 채우는 일은 `S5-D2`의 `discovery_service`가 `vcs_file_probe`로 수행한다.

판정 순서는 계획 4.2 그대로다: 확인 실패 → 메타데이터 충돌 → `.git` 디렉터리 → `.git` 파일 → `.svn` → bare 휴리스틱 → 비저장소.

- 확인 실패(`probe_failed`)가 가장 먼저다. 신뢰할 수 없는 표식으로 종류를 판정하면 안 된다.
- bare 휴리스틱은 `HEAD`+`objects`+`refs` 세 표식이 **모두** 있을 때만 인정한다. 판정 결과의 kind는 `git`으로 남긴다. 목록에는 "Git bare 저장소라서 제외"라는 정보가 필요하기 때문이다.
- 작업 복사본 표식과 bare 표식이 함께 있으면 작업 복사본이 우선한다.

### 2.3 정렬 규칙

`discovery_candidate_before`는 이름의 ASCII 대소문자 무시 오름차순, 대소문자만 다른 이름은 code unit, 이름까지 같으면 절대 경로 순서다. 비ASCII 이름에는 대소문자 접기를 적용하지 않는다. UTF-8 code unit 비교는 code point 순서와 같아 로캘 없이 결정적이다.

### 2.4 Win32 열거 구현

- `FindFirstFileExW` + `FindExInfoBasic` + `FIND_FIRST_EX_LARGE_FETCH`를 사용하고 `.`과 `..`을 제외한다.
- reparse point 여부는 열거가 함께 돌려주는 `FILE_ATTRIBUTE_REPARSE_POINT`에서 얻는다. 자식마다 속성을 다시 조회하지 않는다.
- `MAX_PATH` 초과 경로를 위해 `\\?\` 확장 접두어를 붙인다. `win32_vcs_file_probe`와 같은 규칙이며 그쪽 helper가 파일 내부에 있어 공유하는 대신 같은 규칙을 유지했다.
- 상대 경로는 OS 호출 없이 거부하고 Win32 오류 번호를 남기지 않는다. 계약 위반과 OS 실패를 구분하기 위해서다.
- 패턴에 일치가 없는 `ERROR_FILE_NOT_FOUND`는 실패가 아니라 빈 목록이다.
- 반복 중간의 실패는 성공으로 보고하지 않는다. 끊긴 목록을 성공으로 내보내면 누락된 자식이 조용히 사라진다.
- UTF-8로 표현할 수 없는 이름은 목록에서 빼되 `unreadable_name_count`로 개수를 남긴다.
- find handle은 RAII로 감싸 예외 경로에서도 새지 않는다.

### 2.5 fake enumerator

`fake_directory_enumerator`는 등록한 경로의 목록만 돌려주고 등록하지 않은 경로는 `ERROR_PATH_NOT_FOUND`(3)로 실패한다. 경로 비교는 기존 `fake_vcs_file_probe`와 같게 ASCII 대소문자와 구분자를 무시한다. `enumeration_count()`는 `S5-D2`에서 취소 뒤 열거가 이어지지 않는 것을 단정하는 데 쓴다.
