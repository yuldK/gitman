# 단계 2 `S2-D3-CODE` 검증 기록 - 2026-08-15

## 1. 결과

`.version-list` project path의 Windows 정규화, filesystem 상태 조회와 중복 경로 판정 production code 구현을 완료했다. schema parser는 filesystem과 무관한 상태로 유지하고, 명시적인 workspace path resolution 단계가 parsed document를 후처리하도록 분리했다. 사용자가 작성을 지시해 코드 검수를 승인했다.

이번 체크포인트에서는 새 test source와 fixture를 작성하거나 기존 test를 변경하지 않았다. 기존 CTest 34개만 회귀 실행했다.

## 2. 구현 범위

| 항목 | 구현 내용 |
| --- | --- |
| UTF 경계 | public API는 `std::u8string`만 사용하고 Win32 adapter 내부에서 UTF-16으로 변환한다. |
| 상대 경로 | process working directory가 아니라 workspace document의 상위 디렉터리를 기준으로 절대 경로를 만든다. |
| lexical 정규화 | `.` 및 `..`, slash 방향, 중복 separator와 root 이외의 trailing separator를 정리한다. |
| Windows path | absolute drive, UNC와 지원되는 `\\?\` drive 및 UNC prefix를 처리한다. device namespace와 drive-relative 및 root-relative처럼 기준이 모호한 형식은 거부한다. |
| long path | filesystem 조회 시 extended-length Win32 path를 사용한다. |
| path 상태 | `available`, `missing`, `inaccessible`, `not_directory`와 `invalid`를 구분하고 native error를 보존한다. |
| diagnostic | 상태 warning과 invalid path error에 원본 document path, JSON pointer, 원래 project index 및 ID를 기록한다. |
| 중복 판정 | 정규화된 UTF-16 path를 `CompareStringOrdinal`의 case-insensitive ordinal 규칙으로 비교하고 먼저 나온 유효 project만 유지한다. |
| schema 연결 | parser shadow에 유효 project의 원래 JSON index를 보존해 앞 항목이 schema 오류로 제외되어도 path diagnostic 위치가 어긋나지 않게 한다. |

filesystem resolution은 `resolve_workspace_document_paths`를 호출할 때만 적용된다. 따라서 순수 schema parse 결과는 기존 계약대로 `unchecked`를 유지하며, 단계 4의 store load pipeline이 parse 뒤 resolution을 명시적으로 호출할 수 있다.

symlink, junction, Git worktree와 실제 file identity 비교는 승인된 계획대로 단계 5까지 수행하지 않는다.

## 3. target 및 의존성

- `gitman_win32_platform` target을 추가해 UTF 변환과 project filesystem adapter를 UI 및 Skia target에서 분리했다.
- `gitman_workspace`는 path adapter를 private dependency로 사용하며 public header에는 Win32 type을 노출하지 않는다.
- 기존 `gitman_win32`는 공용 platform target을 사용하므로 UTF 변환 구현은 한 번만 링크된다.
- `workspace_document_paths` public header에는 nlohmann/json, Win32와 Skia header가 노출되지 않는다.

| 검증 | 결과 |

build child process는 기존과 같이 중복 `PATH`/`Path`를 하나의 `Path`로 정규화했다. VS2026 build는 기존 sandbox FileTracker 제한 때문에 host 권한에서 실행했다.

## 6. 구현 중 검토 결과

지원되는 extended path prefix를 drive 및 UNC 형식으로 제한하고 device 및 volume namespace가 상대 경로로 잘못 해석되지 않도록 제출 전에 syntax 경계를 보완했다. 현재 알려진 미수정 production 결함은 없다.

## 7. 다음 검수 게이트

사용자 승인에 따라 `S2-D3-TEST`에서만 다음 test를 추가한다.

- absolute drive, UNC와 document 기준 상대 경로
- `.`, `..`, slash, 중복 및 trailing separator
- 대소문자 차이를 포함한 lexical duplicate
- 한글, emoji, 공백과 long path
- 실제 임시 directory, missing path와 일반 file 상태
- invalid UTF-8 및 잘못된 Windows path syntax
- schema 오류 뒤에도 유지되는 원래 project index diagnostic

test가 production 결함을 드러내더라도 같은 체크포인트에서 production source를 수정하지 않고 `S2-D3-FIX` 검수 대상으로 기록한다.
