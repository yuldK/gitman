`S4-D2-CODE`가 만든 Git 로컬 조회 경로의 test를 작성했다. 고정 출력 파서 test, `fake_process_runner` 기반 명령 조립 및 snapshot 변환 test, 실제 `git.exe`로 임시 저장소를 만드는 통합 test다.

### 2.1 명령 조립 test

- `rev-parse` 인자가 `--absolute-git-dir --is-bare-repository --is-inside-work-tree --show-toplevel` 순서인지 단정한다. 실패할 수 있는 인자가 마지막이어야 앞의 값으로 배치를 판정할 수 있다.
- `status` 인자가 `--porcelain=v2 --branch --untracked-files=normal --ignored=no`인지, **어떤 인자에도 `-z`가 없는지** 단정한다.
- `status`만 레코드 상한이 크고 `rev-parse`는 기본값인지 단정한다.
- 두 요청이 공통 `-c` 인자 순서, 30초 timeout, 8 MiB 캡처 상한, `active_code_page_fallback`, 비대화형 환경 override를 갖추고 단계 3의 `validate_process_request`를 통과하는지 단정한다.
- 로캘 강제 변수(`LC_ALL`, `LANG`)가 없는지도 함께 단정한다.

### 2.2 파서 test

고정 fixture 4종(`status-clean`, `status-dirty-rename`, `status-conflicted`, `status-detached` 및 `status-unborn`)은 실제 Git 출력을 그대로 저장한 것이다. 파서가 실제 형식에서 벗어나면 바로 실패한다.

- `status-dirty-rename` fixture는 rename 레코드에 **공백·한글·emoji가 든 경로**와 TAB 구분자를 담고 있다. 새 경로와 원래 경로를 각각 정확히 읽는지 단정한다.
- 인용 해제는 `\n`, `\t`, `\r`, `\"`, `\\`, `\a\b\f\v`, 8진 이스케이프, 끊긴 이스케이프, 짝이 맞지 않는 따옴표까지 다룬다. 8진 이스케이프가 UTF-8 sequence로 복원되는 것도 단정한다.
- 개행이 든 경로가 인용 덕분에 한 레코드로 남는지 단정한다. `-z`를 쓰지 않기로 한 결정의 근거를 test로 고정한 항목이다.
- 알 수 없는 헤더(`# stash 3`, `# branch.future`)가 판정을 깨지 않는지 단정한다.
- 잘못된 `branch.ab` 4종(`2 -3`, `+2`, `+x -3`, `+2 +3`)을 무시하는지 단정한다.
- 해석하지 못한 레코드, 필드가 모자란 레코드, 경로가 빈 레코드, XY가 두 글자가 아닌 레코드를 세는지와 그때 작업 트리 상태가 `unknown`이 되는지 단정한다.
- 무시된(`!`) 항목이 어느 수에도 들어가지 않고, 변경이 없는 `1 ..` 항목도 세지 않는 것을 단정한다.
- bare 저장소의 세 줄 출력이 해석되고 `--show-toplevel` 실패가 판정을 막지 않는지 단정한다.

### 2.3 provider test

`fake_process_runner`가 기록한 요청으로 "이 조건에서 어떤 명령을 만들었는가"를 직접 단정한다.

| 조건 | 단정 |
| --- | --- |
| 도구 부재 | `tool_unavailable`, 오류 아님, **요청 0개** |
| 상대 경로 | `path_unavailable`, **요청 0개** |
| 사라진 경로 | `path_unavailable`, `path_missing` 진단, **요청 0개** |
| 정상 | 요청 2개, 순서가 `rev-parse` → `status`, 실행 파일과 작업 디렉터리 일치, `fetch` 인자 없음 |
| 저장소 아님 | `not_a_repository`, status를 실행하지 않음(요청 1개) |
| bare, git dir 안 | `unsupported_layout`, status를 실행하지 않음 |
| timeout, 시작 실패, 내부 오류 | `unknown`과 단계 3 진단 승격 |
| 취소 | `unknown`과 `process_cancelled`. 저장소 아님으로 오판하지 않음 |
| status 실패 | `unknown`이지만 저장소 루트는 보존 |
| 해석 실패 | `ready`이되 작업 트리 `unknown`, warning 진단 |
| 미구현 4개 동작 | `executed == false`, **요청 0개** |

저장소 아님 판정 test는 **한국어 Git 메시지**(`치명적: Git 저장소가 아닙니다`)를 stderr로 준다. 분류가 메시지 본문이 아니라 "정상 종료했는데 출력이 없다"는 구조적 신호로 이뤄지는 것을 언어에 의존하지 않고 단정하기 위해서다.

ahead/behind 4조합이 `up_to_date`, `ahead`, `behind`, `diverged`로 매핑되는지, upstream이 없으면 `comparison`이 `none`이고 `sync_state`가 `unknown`으로 남는지도 단정한다.

표식 판정은 merge, cherry-pick, revert, bisect(파일)와 rebase(디렉터리)를 나눠 확인하고, 같은 이름의 파일은 rebase 표식으로 인정하지 않는 것과 linked worktree 전용 디렉터리를 보는 것을 단정한다. `index.lock`만 있을 때 `operation_in_progress()`가 거짓인 것도 고정했다.

### 2.4 통합 test

`git_repository_fixture`가 임시 디렉터리에 실제 저장소를 만든다. 도구가 없으면 `SKIP`한다. 임시 디렉터리는 실패해도 남지 않도록 소멸자에서 지운다.

호스트 설정과 분리하려고 모든 준비 명령에 `HOME`, `USERPROFILE`, `XDG_CONFIG_HOME`을 임시 디렉터리로, `GIT_CONFIG_NOSYSTEM=1`과 없는 `GIT_CONFIG_GLOBAL`을 준다. 커밋 저자와 시각도 환경 변수로 고정한다. 이렇게 하지 않으면 사용자의 `core.autocrlf`나 서명 설정에 따라 결과가 달라진다. 준비 명령은 `-c core.autocrlf=false -c commit.gpgsign=false`도 함께 쓴다.

| test | 확인 |
| --- | --- |
| upstream이 있는 정상 저장소 | `ready`, `main`, 40자 커밋 ID, `clean`, `comparison=local`, `origin/main`, `up_to_date`, 진단 없음 |
| upstream보다 앞선 저장소 | `ahead` 1, `behind` 0 |

| detached HEAD | `(detached) ` 접두어와 7자리 커밋 ID, 로컬 리비전과 접두사 일치 |

마지막 항목은 로컬 조회가 원격을 건드리지 않는다는 것을 실제 실행으로 확인한다. 원격에 접근하면 지연이나 실패가 나타난다.

## 3. 확인한 동작과 기록할 사실

- `--untracked-files=normal`은 미추적 **디렉터리를 항목 하나로 접어서** 보고한다(`? sub dir/`). 따라서 `untracked_count`는 파일 수가 아니라 Git이 보고한 항목 수다. 카드 표시 방식은 단계 6에서 정한다.
- `core.quotepath=false`에서도 Git은 제어 문자, `"`와 `\`가 든 경로를 C 인용으로 감싼다. 실제 출력으로 확인했고 파서 test로 고정했다.
- Windows에서는 파일 이름에 개행과 따옴표를 쓸 수 없어 인용이 실제로 필요한 상황은 드물다. 그래도 다른 플랫폼에서 만들어진 저장소를 열 수 있으므로 인용 해제를 유지한다.
- 통합 test는 실제 Git이 있는 이 호스트에서 12개 모두 실행됐다. Git이 없는 환경에서만 skip된다.
