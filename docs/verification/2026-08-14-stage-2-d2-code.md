# 단계 2 `S2-D2-CODE` 검증 기록 - 2026-08-14

## 1. 결과

schema version 1의 `.verison-list` JSON parser production code 구현을 완료했다. 문서 수준 오류는 document를 반환하지 않고, project 수준 오류는 해당 항목만 제외하면서 나머지 유효 project를 반환한다. 사용자가 진행을 지시해 코드 검수를 승인했다.

이번 체크포인트에서는 새 test source와 fixture를 작성하지 않았다. 기존 CTest 26개만 회귀 실행했다.

## 2. 구현 범위

| 항목 | 구현 내용 |
| --- | --- |
| public 경계 | `workspace_document_parse_result`가 domain document, 구조화 diagnostic와 원문 shadow를 반환하며 public header에 JSON library type을 노출하지 않는다. |
| schema dispatch | 필수 정수 `schema_version`을 검사하고 version 0 및 음수는 이전 schema, version 2 이상은 미래 schema로 거부한다. |
| document 검증 | malformed JSON, object가 아닌 root, 누락되거나 배열이 아닌 `projects`를 문서 수준 오류로 반환한다. |
| project parsing | `id`, `path`, optional field와 기본값을 읽고 잘못된 항목만 제외한다. |
| 중복 ID | 먼저 나온 유효 ID를 유지하고 이후 중복 project를 오류로 제외한다. |
| unknown field | top-level 및 project unknown field마다 warning과 JSON pointer를 반환하고 입력 JSON byte를 shadow에 그대로 보존한다. |
| diagnostic 위치 | 문서 경로, JSON pointer, project index와 가능한 project ID를 함께 기록한다. |
| 보조 계약 | 결과의 error 및 warning 존재 여부를 확인하는 함수를 제공한다. |

경로 정규화, 중복 정규화 경로 판정과 filesystem 상태 확인은 `S2-D3-CODE`, shadow를 반영한 serialize 및 저장은 `S2-D4-CODE` 범위이므로 이번 구현에 포함하지 않았다.

## 3. 변경 파일

- `src/infrastructure/json_workspace_document.h`
- `src/infrastructure/json_workspace_document.cpp`

`tests/` 아래의 unstaged 변경은 없으며 schema parser test와 fixture는 아직 추가하지 않았다.

## 4. 검증 결과

| 검증 | 결과 |
| --- | --- |
| VS2022 Debug build | `gitman_workspace`를 포함해 통과 |
| `ctest --preset vs2022-debug --output-on-failure` | 기존 test 26/26 통과 |
| VS2026 Debug build | host 환경에서 `gitman_workspace`를 포함해 통과 |
| `ctest --preset vs2026-debug --output-on-failure` | 기존 test 26/26 통과 |
| clang-format dry run | 신규 infrastructure header 및 source 통과 |
| source style | 86개 파일 통과 |
| `git diff --check` 및 `git diff --cached --check` | 통과 |
| public dependency 경계 | public header에 nlohmann/json, Win32와 Skia 참조 없음 |
| 새 schema parser test | 작성하지 않음 |

VS2022 build는 build child process의 중복 `PATH`/`Path`를 하나로 정규화해 실행했다. VS2026 build는 기존 sandbox FileTracker 제한 때문에 host 권한에서 실행했다.

## 5. 구현 중 검토 결과

초기 구현 검토에서 unsigned JSON number로 해석되는 version 0도 이전 schema 오류가 되어야 함을 확인해 제출 전에 version dispatch를 보완했다. 별도 test 구간에서 발견한 production 결함은 아니며, 현재 알려진 미수정 결함은 없다.

## 6. 다음 검수 게이트

사용자 승인에 따라 `S2-D2-TEST`에서만 다음 test와 fixture를 추가한다.

- 정상 최소 및 전체 문서와 빈 projects
- malformed JSON, 잘못된 root, schema version과 projects type
- project optional 기본값, 필수 field 및 type 오류와 부분 성공
- 중복 ID와 잘못된 VCS hint
- unknown top-level 및 project field warning과 원문 shadow 보존
- version 0, 음수 및 미래 version 거부

test가 production 결함을 드러내더라도 같은 체크포인트에서 production source를 수정하지 않고 `S2-D2-FIX` 검수 대상으로 기록한다.
