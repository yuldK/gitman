| 경로 | 만들어진 명령 |
| --- | --- |
| 빈 대상, 다른 저장소 종류의 대상 | 0개. 조회조차 하지 않는다 |
| 도구 부재 | 0개 |

### 2.2 후보 목록

- remote 후보가 먼저, local branch가 뒤에 온다.
- 심볼릭 ref는 후보가 아니다.
- 같은 branch 이름이 여러 remote에 있어도 합치지 않는다.
- remote 후보로 도달할 수 있는 local branch는 중복해 넣지 않는다. **upstream이 다른 remote를 가리키면 local 후보로 남는다**는 반대 경우도 함께 단정했다. 이 규칙이 없으면 그 branch로 전환할 방법이 사라진다.
- 새로 고치지 않은 remote의 후보만 `stale`이고 local 후보는 `stale`이 될 수 없다.
- `/`가 든 remote 이름을 가장 긴 접두사로 나누고, 설정에 없는 remote가 남긴 tracking ref는 첫 조각으로 나눠 후보에 남긴다.
- fetch 대상 선택 6종(`preferred_remote`, 지정 값 부재, 유일, 모호, remote 없음, 빈 목록)을 전수 단정했다.

### 2.3 검증 규칙

거부 사유 8종을 각각 고정하고 **우선순위 자체도 단정했다.** 사유를 하나씩 없애면 다음 사유가 나온다.

작업 트리 위험 판정은 dirty, 충돌, **미상**, 진행 중 작업, `index.lock` 5종을 전수 확인한다. 미상 상태를 안전으로 보지 않는다는 것이 보호 정책의 방향이다.

tracking branch는 확인 전에는 `tracking_branch_confirmation_required`로 되돌아오고 `requires_tracking_branch_confirmation`이 켜진다. `tracking_branch_confirmed`를 켜면 승인된다. **확인했더라도 실제 차단 사유가 있으면 그것이 우선한다**는 것도 단정했다.

upstream이 **없는** local branch가 충돌이 아니라는 것과, detached HEAD에서는 어떤 branch도 현재가 아니라는 것을 함께 고정했다.

SVN은 URL 형식 판정 14종, 허용 목록 밖, 목록에 있지만 형식이 잘못된 값(메시지에 그 값이 들어간다), 현재 위치, 작업 복사본 상태, 저장소 root 및 UUID 대조 7종을 다룬다. **대상 값을 읽지 못한 것(`target_unreachable`)과 값이 다른 것(`repository_mismatch`)을 구분**하고, 현재 작업 복사본의 값을 모르면 통과시키지 않는 것도 단정했다.

### 2.4 실패 분류

전환 실패의 분류가 로캘 독립 신호로만 이뤄지는 것을 확인한다. timeout, 취소와 한국어 메시지의 미분류 실패를 각각 `process_timed_out`, `process_cancelled`, `vcs_command_failed`로 고정했다. 실패해도 사후 재조회를 수행하고 `executed`가 참인 것도 함께 단정한다.

### 2.5 실제 Git 통합 test

호스트 Git 2.52.0으로 `main`과 `feature` 두 branch를 담은 bare 원격과 clone을 만들어 확인한다. Git이 없으면 skip한다.

| test | 확인 |
| --- | --- |
| 후보 목록 | `origin/main`과 `origin/feature`가 나오고 clone이 만든 `origin/HEAD`는 제외된다. local `main`은 중복 항목이 되지 않는다. fetch에 성공했으므로 `stale`이 아니다 |
| tracking branch 생성 | 확인 전에는 거부되고 **branch가 실제로 만들어지지 않는다**(후보가 여전히 생성을 요구한다). 확인 후에는 **실제로 만들어 전환하고** 사후 조회가 `feature`와 upstream `origin/feature`를 보고한다 |
| 기존 branch 이동 | **실제로 `main`으로 전환**되고, 같은 대상을 다시 고르면 `already_on_target`으로 명령을 만들지 않는다 |
| 안전하지 않은 저장소 | 실제 `git worktree add`가 잡은 branch를 `target_in_use`로, dirty 작업 트리를 `working_tree_unsafe`로 거부하고 작업 트리를 그대로 둔다 |
| 없는 대상 | `--no-guess`가 막기 전에 검증이 먼저 `target_not_found`로 거른다 |

두 번째 test가 이 구간의 핵심이다. "명시적인 사용자 확인 후에만 tracking branch를 만든다"는 ADR-003 정책이 실제 Git에서 그대로 동작하는 것을 보여 준다.

## 3. 발견한 결함

없다. 작성한 test가 모두 처음부터 통과했고 production 동작을 고칠 이유를 찾지 못했다.

test를 쓰면서 확인한 사항 두 가지를 기록해 둔다.

1. Git provider의 dirty 판정은 후보 목록을 만든 **뒤에** 나온다. 검증이 재조회 다음에 오기 때문이며, 그 사이 명령은 모두 읽기 전용 조회다. 중요한 것은 `switch` 명령이 하나도 없다는 사실이고 test는 그것을 단정한다.
2. SVN 전환에서 현재 URL 조회는 허용 목록 검증보다 **앞선다.** `already_on_target`을 판정하려면 현재 위치를 알아야 한다. 이 조회는 작업 복사본 로컬 정보라 네트워크를 쓰지 않으며, 대상 URL을 확인하는 원격 조회는 로컬 검증을 모두 통과한 뒤에만 나간다.
