# 종료 저장 안정화 검증 (2026-11-05)

## 1. 기준과 범위

- 사용자 지시로 기존 luil 갱신·앱 연결을 `31aedb1`로 커밋했다. 브랜치는
  `codex/luil-integration-shutdown`이며 push하지 않았다.
- 이 기록의 안정화는 그 커밋 뒤의 별도 변경이다. luil 핀은 `077262e` 그대로이며
  luil 내부를 바꾸지 않고 Gitman의 저장 결과 처리와 worker 종료 순서를 고쳤다.

## 2. 문제와 수정

기존 driver는 cancel 뒤 close 이외의 메시지를 버렸다. 종료 직전 창 배치와 저장 결과도
버려지고, controller는 진행 중인 저장이 있는데도 이전 revision·shadow로 마지막 저장을
미리 제출했다. worker가 끝나더라도 마지막 모델이 남지 않을 수 있었다.

1. cancel 뒤 close 이전의 저장 결과는 보관하고, 마지막 창 배치는 받는다. close 이후에는
   문서 저장·앱 설정 읽기/저장 결과만 처리하며 일반 입력·조회·기능 실행은 재개하지 않는다.
2. 진행 중인 저장은 그대로 두고 마지막 변경·창 배치를 합친다. 결과의 새 revision·shadow를
   받은 다음 마지막 저장을 낸다. 시작 직후 닫아도 읽은 설정 위에 마지막 배치를 합친다.
3. `shutdown_completed()`는 마지막 저장 결과까지 처리한 뒤 참이다. luil의 close 대기 예산
   3초를 넘어도 worker 큐를 먼저 닫지 않고, logic이 이어 낼 저장까지 처리한 뒤 닫고 join한다.
   조건 변수로 기다리며 host가 faulted이면 기존 정리 경로를 유지한다.
4. 제출 거부·쓰기 실패도 결과 상태로 남겨 끝나지 않는 저장 대기를 만들지 않는다. 실패를
   성공으로 바꾸거나 원본 revision 검사를 건너뛰지 않는다. 종료 중 tree는 다시 짓지 않고
   마지막 view에 결과·진단을 남긴다.
5. 실제 확인에서 발견한 `기다리지 않고 종료` 문구 잘림은 고정 버튼 폭 대신 글자 실측 크기로
   고쳤다. 버튼 최소 폭은 유지하며 시스템 텍스트 크기도 측정에 반영한다.

## 3. 자동 검사

| 검사 | 결과 |

| 사용 설명서 HTML 생성·일치 | h2 22개·h3 57개, 문제 0 |

건너뜀은 네트워크 test 미설정 두 건과 실제 SVN 미설치 한 건이다. 새 case는 6개다:
문서 revision 순서, 늦은 앱 설정 읽기, 앞 저장 shadow의 사용, 실제 host의 worker 대기,
문서·앱 설정 제출 거부. 실제 host 검사는 첫 쓰기를 3초 넘게 붙잡고 성공·실패 결과를 모두
본다. 실행 경계만 대역이고 host·logic·worker thread·relay는 실제 조립이다.

기존 앱 설정 검사는 더는 마지막 저장을 미리 줄 세운다고 가정하지 않으며 앞 결과를 먼저
보낸다. 기능 fixture가 준비 요청을 버리던 부분은 metadata로 남겨, 종료 검사가 진행 중인
초기 앱 설정 저장도 명시적으로 마치게 했다.

로그는 `build/shutdown-storage-{debug,release}-{build,ctest}.log`, 최종 빌드는
`build/shutdown-storage-{debug,release}-final-build.log`, 영향 범위는
`build/shutdown-storage-targeted.log`·`build/shutdown-storage-ui-regression.log`다.

## 4. 실제 앱: UIA와 지연된 파일 I/O

사용자 화면 대신 격리 데스크톱, 임시 문서와 전용 앱 설정을 썼다. Windows oplock으로 임시
문서의 저장 I/O만 붙잡았다가 해제했다. UIA로 경로 표시를 바꾸고 창을 1600×900으로 조절한
뒤 대기·종료·취소를 조작했다. 원문을 반복 읽으면 atomic 교체와 경합하므로 교체 대기는
파일 metadata로 하고 내용은 종료 뒤 읽는다.

| 경로 | 이전 실행 파일 | 수정본 |
| --- | --- | --- |
| 5초 뒤 `기다리지 않고 종료` | 마지막 창 배치 대신 1920×1080이 남음 | 경로 표시 변경과 1600×900 모두 저장 |
| 앱에만 WM_ENDSESSION 전송, I/O 3.5초 지연 | 1920×1080이 남음 | 1600×900 저장 |
| 저장 성공 뒤 자동 종료 | 비교 기준으로 쓰지 않음 | 다시 누르지 않고 종료, 마지막 값 저장 |
| 대기 취소 뒤 저장 성공 | 비교 기준으로 쓰지 않음 | 앱 유지 확인 후 새 닫기로 종료, 마지막 값 저장 |

저장 중 `종료`가 비활성이고 5초 뒤 종료 선택이 활성화되는 것도 실제 UIA로 확인했다.
폭 수정 뒤 같은 경로를 다시 실행해 전체 버튼 문구가 보이는 캡처와 마지막 값 저장을 확인했다.
세션 검사는 이 앱의 WM_ENDSESSION 경로를 직접 실행한 것이며 Windows 전체 로그오프는 하지
않았다. 앱과 oplock 도구를 정리했고 사용자 설정·입력 장치·작업 저장소는 건드리지 않았다.

근거는 `build/shutdown-storage-uia/probe.ps1`, `oplock_probe.cpp`·`.exe`, 각 case의 JSON·로그다.
이전은 `before-force`, `before-session`, 수정 후는 `after-wait`, `after-cancel-safe`,
`after-session`, 최종 폭 수정은 `after-force-wide`다. 캡처 `after-force-wide/waiting.png`와
`expired.png`는 실제 창이다. build 산출물은 커밋하지 않는다.

## 5. 확인 범위

후속: 이 기록의 안정화는 사용자 지시로 `0648390`에 커밋했다. 배치 사전 조회의 UNC 취소는
[다음 검증](2026-11-06-cmd-inspection.md)에서 별도로 구현했다. 아래 후속 목록은 당시 시점이다.

- 유한한 I/O 지연에서 마지막 저장 결과까지 처리함을 확인했다. 5초는 확인 창의 대기 상한이며
  전체 파일 I/O 정리 시간의 상한은 아니다. 영구 I/O 정지와 Windows의 강제 프로세스 종료까지
  완료를 보장하는 변경은 아니다. 닿지 않는 UNC와 store 교체 재시도는 별도 후속이다.
- 느린 저장 대기·취소·상한 뒤 종료·앱 세션 종료 경로는 이제 실제 앱 검사도 끝났다.
  내레이터 음성·경고음 청취, 전역 텍스트 150%·고대비, conhost 전환은 별도 확인이다.
  전역 설정을 바꿀 때만 사용자의 작업 중단 구간을 먼저 정한다. 이번에는 중단이 필요 없었다.
