## 2. 구현 내용

- **progress record 접기** (stage-8-plan 5.3): 필터 적용 후 연속된 progress
  record(단독 `\r` 진행 표시)는 마지막 하나만 표시 줄이 되고 "(진행 표시 N줄
  접힘)" 표식이 붙는다. 접기 규칙은 `build_log_display_lines`와
  `log_display_line_count`(할당 없는 count 전용)로 `presentation/log_presentation`
  한 곳에 있고, logic의 스크롤 한계 계산과 렌더러가 같은 함수를 써서 그리기와
  한계가 어긋나지 않는다.
  - **ring buffer와 복사는 접지 않는다.** `log_view_model.records`(필터 적용,
    비접힘)는 복사용으로 유지되고 새 `lines`(접힘)가 렌더링·스크롤용이다. 접힘
    계산은 필터를 통과한 record만 대상으로 한다 (필터 조합 규칙).
- **시각적 스크롤 막대**: 카드 목록의 `scrollbar_element`를 일반화해(element id와
  scroll message factory 주입) 로그 pane 본문 오른쪽에 세웠다. 카드 목록용 기존
  조립은 위임 생성자로 유지되어 동작이 바뀌지 않는다.
  - 끌기·track 클릭은 `log_scroll_intent`로 흐르므로 기존 자동 스크롤 규칙(위로
    끌면 꺼지고 맨 아래 도달로 다시 켜짐)이 그대로 적용된다.
  - thumb 계산의 내용 높이는 접힌 표시 줄 기준이라 logic의 한계와 일치한다.
  - 막대가 보이면 본문 글자 폭이 막대를 피해 줄어든다.
- `log_view_element` 생성자가 본문 높이(물리 픽셀)와 배율을 받는다. tree 빌드가
  `compute_list_layout`(arrange와 같은 함수·조건)으로 미리 계산해 넘긴다.

## 3. 테스트

새 test 4개 (전체 CTest 610 → **614**).

- 접기 규칙: 연속 run은 마지막만 남고 접힌 수 기록, 길이 1 run은 접히지 않음,
  줄 끝 run flush, count 함수와 build 함수의 일치, 필터에 걸러진 record는 run
  계산에서도 제외.
- view snapshot: lines에 접힘 반영(진행 40줄 → 표시 1줄, collapsed 39),
  records는 비접힘 유지(복사 보존), 접힌 표시 줄 기준의 스크롤 한계.
- UI: 긴 로그에서 pane 스크롤 막대 표시와 끌기의 `log_scroll_intent` 변환(음수
  delta), 짧은 로그에서 막대 숨김.

## 5. 비고

- 접힌 진행 표시의 원본 record는 buffer에 남아 있으므로 복사 결과와 지우기 전
  진단에는 전체 내용이 보존된다.
- 접기는 record의 `progress` 표식만 기준이다. 작업 경계는 lifecycle record가
  run을 끊으므로 실제로는 같은 작업의 진행 표시만 접힌다.
- 단계 7 이월 항목 중 "로그 pane의 시각적 스크롤 막대, progress record 접기"가
  이 체크포인트로 해소됐다.
