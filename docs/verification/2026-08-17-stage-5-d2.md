### 2.2 탐색 실행의 규칙

- **프로세스를 만들지 않는다.** service의 의존성은 `directory_enumerator`, `vcs_file_probe`, `project_path_resolver`뿐이며 `process_runner` 자체를 받지 않는다. 계약 수준에서 프로세스 실행이 불가능하다.
- 루트가 상대 경로면 filesystem을 건드리지 않고 오류로 끝난다. 열거 실패는 Win32 오류 번호를 진단에 담는다.
- 취소는 열거 전과 자식 경계에서 확인한다. 취소되면 그때까지의 후보를 담은 미완료 결과와 warning 진단을 돌려준다.
- 자식별 표식 확인(`collect_repository_markers`)은 probe 결과를 `repository_marker_set`으로 옮기기만 하고 판정은 `S5-D1`의 순수 함수가 소유한다.
- reparse point 자식은 표식을 확인하지 않고 `reparse_point`로 제외한다. 대상이 실제 저장소여도 판정하지 않는 것을 test로 고정했다.
- 중복 표시는 선택 가능한 후보에만 씌운다. 이미 제외된 항목의 사유를 덮으면 사용자가 실제 원인을 볼 수 없다. 비활성 프로젝트와의 중복도 같은 사유다.
- 루트 자체 판정 `root_is_repository`는 작업 복사본과 bare 저장소를 모두 참으로 본다. 둘 다 "저장소 내부 또는 저장소 자체를 스캔했다"는 경고 대상이다.
- 파일 항목은 후보로 만들지 않으며, UTF-8로 읽을 수 없는 이름은 warning 진단으로 알린다.

### 2.3 probe 계약의 한계 명시

현재 `vcs_file_probe`는 존재 여부만 알려 주고 접근 실패를 구분하지 않으므로(단계 4 계약), service가 자식 하나의 `probe_failed`를 켤 방법이 없다. 판정 규칙의 `inaccessible` 분기는 계약이 확장될 때를 위해 유지하며 이 사실을 header 주석과 이 기록에 남긴다. 단계 2 실측(로컬 NTFS는 deny ACE로 속성 조회를 실패시킬 수 없음)과 합치면 실제 환경에서 이 분기가 필요한 경우는 드물다.

### 3.2 `discovery_integration_tests.cpp` (실제 환경 5개)

| test | 확인 내용 |
| --- | --- |
| VCS 없는 혼합 배치 | 실제 `.svn` 표식, 일반 디렉터리, **실제 junction**(`mklink /J`), 파일. junction이 `reparse_point`로 제외 |
| 실제 Git 배치 | 실제 저장소, `git worktree add`가 만든 `.git` 파일 worktree, `git init --bare`, plain의 4종 판정 |
| 실제 중복 감지 | 실제 해석기로 만든 문서 항목과 **구분자가 다른 표기**(`/`)의 중복 일치 |
| 저장소 내부 스캔 | 저장소 루트를 스캔하면 `root_is_repository`가 참이고 `.git` 자식이 선택 불가 |

SVN 경로는 판정이 표식 기반이라 `svn.exe` 없이 실제 filesystem으로 검증된다. junction 생성은 `cmd.exe`의 `mklink /J`를 사용하며(일반 권한으로 가능) 만들 수 없는 환경에서는 해당 test가 이유와 함께 skip된다. 이 호스트에서는 실제로 실행됐다.
