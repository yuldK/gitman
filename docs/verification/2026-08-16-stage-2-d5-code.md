# 단계 2 `S2-D5-CODE` 검증 기록 - 2026-08-16

## 1. 결과

`.verison-list` 작업공간 문서를 Windows shell positional argument로 전달받기 위한 production launch 계약을 구현했다. `application_options`가 선택적인 UTF-8 문서 경로를 보존하며, 기존 `wWinMain`의 UTF-16 인자 변환과 `run_application` 전달 경계를 그대로 사용한다.

VS2022와 VS2026 Debug build 및 기존 전체 CTest 50/50이 모두 통과했다. 이번 체크포인트에서는 새 test source나 fixture를 작성하지 않았으며 현재 상태는 사용자 코드 검수 대기다.

## 2. positional path 계약

| 항목 | 구현 내용 |
| --- | --- |
| 경로 없음 | renderer 및 smoke option만 있는 기존 시작을 허용하고 `workspace_document_path`를 비워 둔다. |
| 단일 경로 | 실행 파일 이름 뒤 option이 아닌 첫 positional argument를 작업공간 문서 경로로 보존한다. |
| option 순서 | 알려진 option과 문서 경로가 앞뒤 어느 순서로 전달돼도 하나의 parser에서 처리한다. |
| 중복 경로 | 두 번째 positional argument는 한 창당 하나의 활성 문서 계약을 위반하므로 오류로 거부한다. |
| 확장자 | Windows 사용 방식을 반영해 ASCII 대소문자를 구분하지 않고 `.verison-list` suffix를 확인한다. 다른 확장자와 `.bak`은 거부한다. |
| unknown option | `--`로 시작하는 미지원 option은 positional path로 해석하지 않고 기존처럼 오류로 거부한다. |
| 원문 보존 | 공백, 한글 및 다른 UTF-8 문자를 포함한 argument byte를 정규화하거나 filesystem 조회하지 않고 그대로 보존한다. |

## 3. store 진입 경계

- `application_options::workspace_document_path`는 후속 composition 또는 logic 계층이 `project_store::load(document_path)`에 넘길 명시적 진입 값이다.
- 현재 `wWinMain`은 모든 argument를 UTF-8로 변환한 뒤 parsed `application_options` 전체를 `run_application`에 전달하므로 별도 Win32 경로 type을 application 계약에 노출하지 않는다.
- 경로의 존재, JSON 내용, backup과 recovery는 이미 구현된 project store가 판단한다. command-line parser는 filesystem I/O를 수행하지 않는다.
- 문서 경로가 없는 경우의 열기 및 새 문서 UI와 실제 app state 연결은 승인된 계획대로 단계 6에 남긴다.
- Windows file association 등록 및 제거는 단계 8 범위이며 이번 구현에 포함하지 않는다.

## 5. 검증 결과

| 검증 | 결과 |
| --- | --- |
| VS2022 Debug build | 변경된 application options와 기존 Win32 진입점을 포함해 통과 |
| `ctest --preset vs2022-debug --output-on-failure` | 기존 전체 50/50 통과 |
| VS2026 Debug build | host 환경에서 변경된 production source를 포함해 통과 |
| `ctest --preset vs2026-debug --output-on-failure` | 기존 전체 50/50 통과 |
| clang-format dry run | 변경 C++ source 및 header 통과 |
| line ending 및 source style | UTF-8 무 BOM, CRLF와 source style 검사 통과 |
| `git diff --check` 및 `git diff --cached --check` | 통과 |
| test source 및 fixture 변경 | 없음 |

build child process는 기존과 같이 중복 `PATH`/`Path`를 하나의 `Path`로 정규화했다. VS2026 build의 최초 sandbox 실행은 기존 FileTracker 제한으로 `E_ACCESSDENIED`가 발생했으며, 같은 build를 host 권한에서 실행해 통과했다.

## 6. 구현 중 검토 결과

확장자 판정은 경로를 바꾸지 않고 고정 ASCII suffix만 대소문자 무시로 비교한다. 따라서 Unicode 경로 원문과 separator는 손실되지 않으며 실제 path 유효성 및 접근 가능성 판단은 store와 Win32 file adapter 경계에 남는다.

aggregate `gitman_format_check`의 기존 `utf8.cpp`, `win32_application.cpp`, `ui_theme.h` 위반은 이번 diff와 무관한 기준선 보류 사항으로 유지한다. 변경한 application options source와 header의 동일 formatter 직접 dry-run은 통과했다.

현재 알려진 launch contract production 결함은 없다. 새 동작의 전용 test는 체크포인트 분리 규칙에 따라 아직 작성하지 않았다.

## 7. 다음 검수 게이트

사용자가 `S2-D5-CODE`를 승인하기 전에는 새 test source나 fixture를 작성하지 않는다. 승인되면 `S2-D5-TEST`에서만 경로 없음, 정상 경로, 중복 positional path와 잘못된 확장자 test를 추가한다.

test가 production 결함을 드러내더라도 같은 체크포인트에서 production source를 수정하지 않고 `S2-D5-FIX` 검수 대상으로 기록한다.
